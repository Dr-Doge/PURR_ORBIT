# 12｜七天开发计划与验收

## 总原则

每天结束时都应保留一个可以运行的版本。先完成“基础工作 → 买盒 → 拆盒 → 卖出 → 日切”的纵向切片，再加入市场和订单，最后替换美术。

## 七天排期

### 第 1 天：工程与灰盒

- 确认 Godot 4.7.1 工程可运行。
- 建立主场景、桌面、相机、灯光和基础 HUD。
- 用方盒搭建快递箱与封条热点。
- 完成鼠标射线和可交互高亮。

**日终交付**：能进入桌面，鼠标能识别封条。

### 第 2 天：完整拆箱手感

- 实现拆箱状态机。
- 完成按住右滑撕封条、按住上滑取物。
- 加入进度容错、失焦取消和简化模式。
- 接入临时音效、镜头反馈和揭晓卡。

**日终交付**：可重复完成快递箱与盲盒两类拆封。

### 第 3 天：内容、库存与经济

- 建立五套系列、30 件内容物、2 件合成款和五档稀有度数据。
- 用整数权重实现各系列概率池（4—8 个权重、总和 10,000）并校验。
- 实现购买、未拆盒库存、藏品库存、出售与回收。
- 实现 `10 → 100 → 1,000 → 10,000 → 100,000` 盒价阶梯、基础快递工作和“盒价 × 2”解锁。
- 加入购买时确定结果、首次发现和 64 位货币。
- 实现 AB／ABC 配对合成：组件校验、原子合成、合成款生成与存档。

**日终交付**：五档开盒、指数赚钱与配对合成循环可玩。

### 第 4 天：天制与动态市场

- 实现 7 日回合、日切和结算。
- 实现新闻、系列指数、单品热度、供货指数与稀有度价格上限。
- 用相对内容期望指数将爆款藏品价格传导至对应盲盒。
- 完成市场面板、完整概率、趋势箭头、价格原因和大数缩写。
- 加入随机种子和当日状态保存。

**日终交付**：内容物可按稀有度膨胀，整盒价格随之变化且仍可购买。

### 第 5 天：订单与完整流程

- 实现三种订单、接取报价快照、匹配、交付和过期。
- 完成订单夹 UI 与到期提醒。
- 接入五档奖励倍率和防止不可能订单的约束。
- 完成第 7 日总资产结算，订单与首次发现奖励不重复计分。

**日终交付**：从第 1 日到第 7 日可完整通关，传说订单可正确处理亿级奖励。

### 第 6 天：表现、教程与存档

- 替换核心箱体与至少 10 个基础藏品模型，用变体覆盖全部 30 个结果与 2 件合成款。
- 完成首次操作引导、32 格收藏册、配对合成演出和设置。
- 接入主要音效、灯光、五档识别和三套揭晓动画模板。
- 完成自动保存与继续游戏。

**日终交付**：五档内容与配对组件可清楚区分，数值膨胀和合成演出有匹配的视听反馈。

### 第 7 天：平衡、修复与构建

- 完成至少 5 次完整七日测试，并额外运行概率与合成模拟。
- 固定各系列权重，只调整首盒时间、解锁阈值、订单倍率、市场传导和合成倍率。
- 检查从 1 到 81,000,000,000 的价格计算、动画和 UI 显示。
- 验证 AB／ABC 合成不会重复扣除组件、不会复制合成款。
- 修复阻断流程、重复发奖、丢失库存、数值溢出和输入卡死问题。
- 导出 Windows 构建，制作简短操作说明与展示素材。

**最终交付**：一份可从头到尾游玩、各系列权重正确、配对合成可用且具有明显长尾膨胀的稳定构建。

## MVP 验收清单

### 流程

- [ ] 新游戏从 0 现金和 3 个快递箱开始。
- [ ] 玩家可以获得现金并购买第一款盲盒。
- [ ] 五个系列均可通过累计经营收入解锁，门槛为目标盒价 × 2。
- [ ] 七日流程能正常推进并进入最终结算。
- [ ] 资金归零后不会永久卡死。

### 拆箱

- [ ] 封条可被找到并高亮。
- [ ] 按住左键向右拖动可完整拆封。
- [ ] 按住左键向上拖动可取出内容物。
- [ ] 松手、失焦、快速拖动不会卡住状态。
- [ ] 各稀有度结果都能显示概率、基础价值、今日价和相对盒价倍率。
- [ ] 配对组件揭晓时显示“配对进度”，并提示集齐可合成完整款。

### 合成

- [ ] AB 款需同时持有左翼、右翼各 1 件才能合成；ABC 款需头、躯干、腿部各 1 件。
- [ ] 合成消耗组件、生成完整款，且不可逆、不产生现金。
- [ ] 组件不足时“合成”按钮不可用并显示缺失项。
- [ ] 合成款有独立收藏格位、市场报价与订单交付资格。
- [ ] 读档后合成款来源记录与组件状态一致，不重复合成、不丢失组件。

### 市场与订单

- [ ] 单品上涨会按相对内容价值指数提高对应盲盒价格。
- [ ] 常见到传说、配对单件与合成款分别遵守各自的市场价格上下限。
- [ ] 星港机神·合体可从 1,350,000,000 上涨到 27,000,000,000，并可通过指定订单达到约 81,000,000,000。
- [ ] 新闻能解释主要涨跌，供货新闻能实际改变盒价。
- [ ] 同日买卖不能无风险套利，组件与合成款之间不能形成现金套利。
- [ ] 三类订单均可完成和过期，报价快照正确且奖励只发一次。

### 数据与存档

- [ ] 五个系列均使用整数权重数组，总和严格为 10,000，权重数与内容物数一致。
- [ ] 每系列模拟抽取 100,000 次后，各稀有度频率落在预设容差内。
- [ ] 购买时锁定开盒结果，读档不能刷新传说与配对组件结果。
- [ ] 日切后价格、新闻、订单报价快照和库存可正确恢复。
- [ ] 所有 30 件开盒内容物都可通过概率池获得，2 件合成款仅能通过合成获得。
- [ ] 从 1 到 81,000,000,000 的货币运算使用 64 位整数且没有溢出或精度丢失。

### 体验

- [ ] 购买前完整公开本系列概率权重。
- [ ] 1280×720 下关键 UI 不遮挡交互区域。
- [ ] 不依赖颜色也能识别涨跌、五档稀有度与配对状态。
- [ ] `K／M／B／T` 缩写、完整数值和价格滚动均不超出界面。
- [ ] 主要揭晓与合成动画可快速跳过或保持短时长。

## 概率模拟容差

| 稀有度 | 目标概率 | 100,000 次容差 |
|---|---:|---:|
| 常见 | 50% | ±1.0 个百分点 |
| 少见 | 30% | ±1.0 个百分点 |
| 稀有 | 10—15% | ±0.5 个百分点 |
| 史诗 | 9% | ±0.5 个百分点 |
| 隐藏／传说 | 1—5% | ±0.2 个百分点 |
| 配对单件 | 0.5% 或 0.33% | ±0.1 个百分点 |

## 砍项顺序

时间不足时从上到下依次删除：

1. 桌面自由旋转与额外相机效果。
2. 收藏品实体摆放，只保留收藏册。
3. 额外新闻动画，只保留新闻卡和数值影响。
4. 稀有度订单，只保留指定款与主题订单。
5. 减少独立模型数量，用材质与附件变体覆盖 30 个数据结果。

不得砍除：两段式拆箱、稳定基础收入、五个价格层级、30 件内容物与 2 件合成款数据、各系列固定权重、AB／ABC 配对合成、指数价值曲线、日切、价格传导和至少一种限时订单。

## 主要风险与对策

| 风险 | 对策 |
|---|---|
| 3D 拖动判定不稳定 | 使用屏幕空间累计位移，不依赖真实撕裂物理 |
| 内容制作量过大 | 模型复用基础体，保持 30 个数据结果和可辨变体 |
| 玩家误以为概率被暗改 | 购买前公开各系列权重，标准池不使用概率保底 |
| 配对款被误卖 | 揭晓与库存明示“配对组件”，出售确认页加二次提醒 |
| 合成逻辑出错 | 合成由库存服务原子执行，验收覆盖重复合成与读档恢复 |
| 市场看似纯随机 | 新闻影响大于噪声，并直接标注价格原因 |
| 长尾奖励导致数值溢出 | 所有货币使用 64 位整数，统一测试百亿级边界 |
| 玩家坏运气软锁 | 每日固定回收收入与空仓低保，不修改开盒概率 |
| 订单无法完成 | 仅从已解锁且可购买的池中生成 |
| 最后一天无法交付 | 截止日结束前允许交付，日终才过期 |

## 发布前最低测试矩阵

- 新游戏完整通关 2 次。
- 固定随机种子通关 1 次。
- 连续最低价值结果通关 1 次。
- 连续高市场波动通关 1 次。
- 每个系列独立模拟抽取 100,000 次并检查概率容差。
- 用调试数据分别触发五档揭晓、AB 合成、ABC 合成和 81,000,000,000 订单结算。
- 验证合成在“组件不足／组件齐全／重复合成／读档恢复”四种场景下行为正确。
- 720p 与 1080p 各检查一次大数值 UI。
- 简化拆箱模式完整通关一次。
