# 11｜验证范围与拓展

v0.26｜2026-09-18。入口：[00_索引](00_索引.md)。**本页是验证与Demo范围建议，未作为已获用户确认的发行范围。**

## 分批验证

| 批次 | 最小内容 | 必须回答的问题 |
| --- | --- | --- |
| A：第一周目 | 基础猫、叠层、工人、喂食器、日光浴、首代币与首轮扭蛋 | 基础操作与自动化是否清楚？首轮没有虫害，能否靠本轮内容收完当期奖池？ |
| B：第二周目 | 继承buff、旧设施恢复、蟑螂、分工、娱乐及新系列 | 熟悉内容是否更快？新问题和新收益能否重新带来探索？ |
| C：第三周目 | 继承buff、祭坛、信号干扰、维护与新系列 | 全局加速是否值得？旧娱乐设备的新故障能否逐步交给工人？ |

按A→B→C验证内容开放与重开的完整体验。上述是机制验证批次，公开Demo包含几周目仍待决定；不能为展示所有功能而让首轮直接开放后续设施。各类特殊猫随来源设施开放，转化分支细节待定。

## 行为检查清单

| 检查场景 | 应观察到的结果 |
| --- | --- |
| 同条件等待连续毛层 | 每层CD相同，层数累积；无收割不自动变库存货币 |
| 相同时间分次收与叠层收 | 后者显著更多；工人不会擅自破坏选定的攒层策略 |
| 收割或娱乐奖励完成 | 只入库一次，不出现额外拾取步骤 |
| 第一周目安装日光浴并久未打理 | 仍不出现蟑螂；首轮事件门槛不能被安装绕过 |
| 第二周目及以后未满足日光浴安装条件 | 不因该机制出现喂食器虫害 |
| 第二周目及以后，安装日光浴后久未打理 | 出虫、失去加成且减产；清虫操作可完成 |
| 巨型猫进食 | 只消灭部分蟑螂，不自动清空所有设备 |
| 猫处于娱乐设施 | 暂停毛球生产，按有效轮次判断换金产出 |
| 招财抛币反面 | 原奖励保留，只有附加道具落空 |
| 第三周目及以后，安装祭坛并出现黑屏 | 受影响设备停止换金产出，捶打后恢复 |
| 未解锁／已解锁工人维护 | 前者不能由工人维修；后者仍需工人执行任务 |
| 节点性能分支未满且周目已开放 | 不因性能分支阻止下一主体；转化失败不阻塞基础推进 |
| 第一周目资金充足／第二周目资金充足 | 仍不能购买娱乐设施／密语祭坛；也不能提前进行相应转化 |
| 第二周目／第三周目到达 | 只开放当期内容资格，不自动赠送娱乐设施／祭坛，不立即令所有设备故障 |
| 多猫、多工人、多设施 | 对象可选、范围清晰、收益可读、岗位积压能被理解 |

毛层、日光浴和触发链的正式参数仍待定；本轮Demo按单独列出的临时实现口径进行验证，测试通过不代表正式方案已定稿。

## 后续拓展方式

| 方向 | 可以扩展什么 | 应保留什么 |
| --- | --- | --- |
| 猫种 | 新设施转化的新能力、对旧需求的部分缓解 | 只直接购买基础猫的当前规则，改变时须明确版本 |
| 设施 | 新收益或操作、与旧系统的新联动 | 新劳动交给工人；避免用机器替代所有岗位 |
| 数量 | 更多猫、更多工人、更多设备 | 可读反馈、可管理的分工、持续有效的摆放选择 |
| 升级树 | 新主体、局部节点簇、已有分支更多等级 | 多路线选择，分支不强制满级，明确升级作用对象 |
| 反馈 | 猫体态、同步范围效果、设施状态 | 简单显眼，产物自动入库 |

上一轮娱乐设施候选灵感尚未逐项选定，列在[12](12_待定决策与变更.md)，不在本轮验证必需内容中。

## 新增长期循环检查

- 首枚代币能在早期触发接触，不依赖已经获得招财猫或外星猫；具体掉落保障待定。
- 首件收藏立刻提供buff，同系列收集度增加后加成增强。
- 抽出收藏后从池移除，继承收藏也不再次出现；空池不扣币。
- 集齐指所有当期可得收藏，不只是每套拿到一件。
- 重启后收藏和buff保留，开局即有效；新系列与旧收藏区分。
- 中断、重复输入和读档不重复扣费、不复制收藏、不丢失继承进度。
- 下周目可抽系列增加，并且早期经营明显更快；剩余代币与重置清单定稿后才能完成切换检查。

完整机制验证应覆盖第一→第二、第二→第三两次切换，即使使用临时小奖池；检查旧安装状态、事件门槛与继承效果。公开Demo包含几周目、系列件数和时长另定，不能把调试小池当作正式内容规模。

## 两小时目标的诊断补充

新增`tests/analyze_pacing.gd`，6种路线×3个固定种子，使用Godot4.7.1现有模型。限制每秒最多一次手动收割，仍不计实际读界面与决策耗时，不能当真人时长。完整经营中位模拟约7.42分钟；只买猫约4.42分钟；不购买约16.23分钟；所有消费乘16约10.90分钟。
