## 叠层公式候选（设计提案）

定义：n为完成的毛层数，B为一层基础产量，M为已生效产量倍率，a为每增加一层的额外增益系数。

候选总产量：`Y(n) = B × M × [n + a × n × (n - 1) / 2]`，其中`a > 0`。

这个候选让第k层贡献`B × M × [1 + a × (k - 1)]`，每层CD仍相同。仅对比单次n层奖励与n次单层奖励，金额比为`1 + a × (n - 1) / 2`；首层常驻且互动耗时变化后，不再代表等时长收益比。公式仅用于试算“层数越多收益明显更高”，尚未确定采用。

| 纯数学示例：a=1、B×M=1 | 等待多层后收割 | n次单层收割的总金额（非等时长） |
| --- | --- | --- |
| 1层 | 1 | 1 |
| 2层 | 3 | 2 |
| 4层 | 10 | 4 |

以上数值不是猫种初值或售价。未确定毛层上限前不能将公式无限外推：无上限且线性增长每层价值，会使持续等待越来越占优。需要验证存钱升级的即时回报能否与等待竞争，再决定上限或高层曲线；不能未经确认取消叠层优势。

## 速度与产量分开

祭坛、外星猫及黑屏维修的公式保留供后续扩展，本Demo收入预算不计这些来源。

| 变量 | 影响 | 试算注意 |
| --- | --- | --- |
| 基础毛层CD | 多久增加一层 | 同一条件下后续每层同CD |
| 喂食产量倍率 | 一次结算拿到多少 | 增益在生长或收割时确定，待D01 |
| 祭坛速度 | 全局生产节奏 | 作用系统与叠加顺序待D04 |
| 外星猫速度 | 周围猫的毛层CD | 范围和多猫重叠待D04 |
| 工人处理能力 | 实际每秒完成多少工作 | 不能用名义产量替代工人来不及处理后的真实收入 |

速度换算候选：若生产速度乘数为S，可用`有效CD = 基础CD / S`。不能同时再对同一来源重复减CD；外星猫的CD缩短与全局速度如何合并，定稿前不填具体百分比。

## 价格、回本与运行率

设计提案：重复购买成本可采用`第k次费用 = 初价 × 增长系数^k`，但猫、工人、设施和各强化分支分别校准。新机制首购用独立定价，不能靠统一指数把关键玩法长期锁死。

估算回本时间：`购买成本 / 每秒新增净收益`。净收益要扣猫粮等持续消耗，并考虑猫被娱乐占用、故障停产和工人不足。一次中奖不能当作稳定的平均收入。

娱乐每秒期望收入候选：`有效运行率 × 获胜概率 × 平均奖品售价 / 单轮时间`。维修前后比较的重点是运行率恢复，不是给维修工人再叠一份奖励。

岗位压力可用`任务到达频率 × 单次占用工时 / 岗位人数`估计。持续超过1意味着积压会增长，是增加工人或调整分工的信号；此计算只用于调试，不必展示给玩家。

## 必须验证的风险

| 风险 | 需要观察的情况 |
| --- | --- |
| 层数升级回报不足 | 初始收第一层用于快速回款；升级后需等待并互动更久，新增收益必须能补偿额外时间 |
| 猫粮持续亏损 | 购买喂食器后净收入倒退；区分故障惩罚与正常经营成本 |
| 加速相乘失控 | 祭坛、外星猫、日光浴叠加让CD趋零 |
| 静电、招财、转化递归 | 一次事件不断生成新的同类事件；判定边界必须先明确 |
| 转化概率卡流程 | 未转成特殊猫时无法赚到下一设施；不要把体验顺序写成随机硬锁 |
| 工人维护收益不明显 | 故障太少导致节点无用，或故障太密让维修永远追不上 |
| 升级提价超过增长 | 玩家进入长时间无选择等待，失去“突破瓶颈”反馈 |

下一轮最少需要一组基础猫CD、单层产量、抚摸耗时、首工人成本与效率、猫粮消耗、娱乐回报和故障频率，才能进行完整数值模拟。当前尚无已验证EA价格表。

## 两批扭蛋的数值框架（费用与曲线仍是提案）

第一批2套×6＝12件，第二批新增4套×6＝24件，累计36件。每抽减少一个剩余名额；每批统一单抽费用若为k，则该批总费用为`k × 件数`。若都暂按每抽1币试算，共需消费36币；**1币单抽只是现原型口径，未由本次消息确定为正式价格。**

设补货时保留代币T，第二批单抽费用k2，则第二阶段需新获得的代币为`max(0, 24 × k2 - T)`。提前囤币必须计入时间模型，不清零、不贬值、不引入未确认的批次专用币。

系列加成从`满套强度 × f(已得件数 / 6)`试算。先定整套效果，再分摊给6件，不能直接复制旧3件套的单件强度。进入第二阶段不重新叠乘已有收藏。

| 风险 | 需要校准的关系 |
| --- | --- |
| 首枚代币迟迟不来 | 早期接触与首抽保障单独校准 |
| 只买猫绕过全部设施 | 旧模型代币只随毛层数量增加；N2现用有效贡献连接增产/娱乐，具体试玩值见17第12节 |
| 只收第一层刷币最优 | 比较等时长单层、多层与工人路线，不按鼠标事件次数直接发币 |
| 第二阶段规模突然失控 | 场地资本＋首批完整buff＋新奖励同时作用，不能按重开初值平衡 |
| 更多收藏放大总buff | 新件数和新系列均增加，按整套及同类总强度控制，不能每件无脑独立相乘 |
| 囤币让第二批瞬间抽空 | 计入首段结余与新币需求，检查正常路线；不通过偷偷清币修复 |
| 第二阶段奖池翻倍却等太久 | 24件应由更高币速支持，不能只按系列数翻倍时间 |
| 新内容尚未体验便抽空 | 调整收益与代币衔接，不加“树满级才能补货”的硬门槛 |

## 一小时经济校准

第一阶段不能靠未开放的娱乐或祭坛完成奖池；第二阶段不计祭坛、外星猫或维修收益。补货时保留资金、粮食、道具、实体、研究、代币与生产进度，后段价格应基于首段结束时的净收入与钱包，而不是开局2只猫。

建议25＋35分钟：按每抽同价且不考虑囤币，12件／25分钟与24件／35分钟意味着后段平均抽取速率约为前段1.43倍。是校准关系而非定时发奖，首枚保障和库存结余都需另算。详细公式、旧诊断及dc参考见[16](16_一小时Demo数值与阶段节奏分析.md)。

## 2026-09-21首层常驻后的重算要求

第一层不再等待长毛CD；收入受玩家互动耗时、小帮手互动耗时与产出后CD限制。必须分别测量单层连续回款和攒层路线，不能沿用“1层每6秒”的旧收入估算。保持多层高单次收益，并校准长期效率优势，而不是把旧等时长结论当作新机制已经满足。

单次互动时间可试`I(n)=I1×[1+b×(n−1)]`，I1＞0、b＞0；这是待验证候选，非已确认线性规律。工作CD可试`C(L)=max(Cmin,C0×r^L)`，Cmin＞0、0＜r＜1；具体参数与现有工效／buff如何组合未定。

工人每轮总占用时间需包含实际找目标、行走、等待层数、互动和工作CD；有重叠时按真实时序计算，不能把所有时间机械相加。首层重复收割也会推进有效贡献，首币保障、36枚阈值、招财抛币和静电触发频率均须复测，旧一小时报告不证明新规则平衡。
