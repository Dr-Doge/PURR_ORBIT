## 接手某项修改时的顺序

1. 说明目标是“概念图／绿幕单图”“画布处理候选”还是“当前游戏猫动画”；定位相应源文件、动作和版本。
2. 对工具工作先看 `Gaming/tools/<工具>/README.md`、当前源码、对应测试与 `Gaming/output/<工具>/` 中该项目的记录；不要只看这份快照文档。密钥、任务与原始输出不要复制到 GitHub 文档里。
3. 生成或编辑后记录源图／视频、动作、方向、处理参数、候选与验收结论。若涉及付费生成，先核对已有 task ID，避免重复提交。
4. 若要接入游戏，把选定导出导入 `毛球满屋/Art/`，修改 SpriteFrames 与运行引用；检查四向动作、脚底锚点、透明边、收割反应时钟和 3D 场景实际画面。通过后更新 [02](02_素材与场景索引.md) 的“当前／候选”状态，再把提交和报告追加到 [01](01_制作与整合日志.md)。
5. 如果只是记录本机实验，保持“未接入”标记；若要让新机器完整复现，还需另行迁移未入库的源码、数据和原始媒体。不能仅靠本目录重建二进制素材。
