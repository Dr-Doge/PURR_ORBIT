## 它的树有什么值得借鉴

以下事实可由配置定位；中文名称是按内部键作的释义，尚未核对官方中文界面。

| 设计结构 | 配置中的证据 | 玩家会面对的选择／设计启发 |
| --- | --- | --- |
| 新主体与属性强化分开 | `SHOP_UNLOCK`与`DIRT_GAIN`等属性分开，另有`COUNT`记录 | 先开放一个新对象，再买实例或强化已有对象；实际购买流程仍需界面确认 |
| 同属性分成多段 | 勺子`DIRT_GAIN`有STAT_ID 0、1两段，各自有等级、价格和前置 | 旧工具在后期重新得到一组值得买的升级，不必被新工具完全替代 |
| 扩容节点也承担阶段门槛 | 勺子第二段产量、动画倍率和暴击概率都引用`COUNT_ADD[1]`等级1 | 一个里程碑同时打开后期成长空间；COUNT_ADD的实际容量算法仍需代码核对 |
| 新系统交叉解锁 | 背包引用蘑菇帮手解锁；铲子与光标范围引用背包解锁 | 玩家在对象、自动化和系统功能之间交替探索，而非只沿一条工具名单往下买 |
| 相同属性有不同价格曲线 | 勺子初段产量增长系数1.6，初段动画倍率与暴击为1.25；蘑菇帮手产量倍率为4 | 不同分支承担小步补强或大额阶段投资，不能统用一条价格曲线 |
| 数量与性能有独立记录 | `COUNT`和`COUNT_ADD`之外另有速度、产量、掉落属性 | 规模扩张和单体效率分开做决策；具体基础上限不能只看字段名字断言 |
| 掉落频率与物品品质分开 | 同一主体具有`LUCK_ITEM_DROP`与`LUCK_ITEM_RARITY` | 可以分别追“经常掉东西”和“掉更好的东西”，与我们的两种掉率口径契合 |
| 收藏可连接属性奖励 | BADGES引用具体`KEY_NODE / KEY_STAT / STAT_ID`，部分属性记录没有普通前置字段 | 树购买之外还有奖励来源；无价格或缺字段记录不能都当成免费树节点 |

## 分段升级与数值样例

| 分支记录 | LEVELS | VALUE_INIT → 每级VALUE_INC | DIRT_BASE / DIRT_GROWTH | 配置指定前置 |
| --- | ---: | --- | --- | --- |
| 勺子产量第一段 | 4 | 1 → ＋1 | 50 / 1.6 | NULL |
| 勺子产量第二段 | 5 | 0 → ＋1 | 500 / 2 | 勺子COUNT_ADD[1]等级1 |
| 勺子动画倍率第一段 | 5 | 1 → ＋0.03 | 35 / 1.25 | 勺子产量[0]等级1 |
| 勺子动画倍率第二段 | 10 | 0 → ＋0.03 | 300 / 1.3 | 勺子COUNT_ADD[1]等级1 |
| 蘑菇帮手等待第一段 | 10 | 3 → −0.1 | 200 / 1.15 | 蘑菇帮手解锁等级1 |
| 蘑菇帮手等待第二段 | 10 | 0 → −0.1 | 1,000 / 1.65 | 蘑菇帮手COUNT_ADD[1]等级1 |
| 蘑菇帮手产量倍率 | 4 | 1 → ＋1 | 5,000 / 4 | 蘑菇帮手COUNT_ADD[0]等级1 |

**解释边界：**本次NodeData脚本已核实同属性各段求和；不能把第二段孤立解释成“零秒等待”或负时间。`ANIMATION_SCALE`只先译为动画倍率，未经代码核对不直接等同于行走速度。暴击具体倍率、稀有度如何合并，也不能只凭属性名断言。

本次已核实基础购买费用生成：当前等级L升到L+1的费用为`roundi(DIRT_BASE × DIRT_GROWTH^L)`。例如勺子首段产量四次基础价格为50、80、128、205。属性各段由NodeData求和；具体效果和其他系统是否调整最终收益仍须对应脚本确认。

## 必须保留的配置疑点

| 疑点 | 已见事实 | 研究时如何处理 |
| --- | --- | --- |
| 数据条目不等于可见树节点 | 168条里142条DEMO_LOCK=0、5条=1、21条未填 | 保留原始标记；原字段保留缺失；运行时已核实默认0，仍不代表168条都对应树按钮 |
| 后续节点可能被间接挡住 | `MOLE_GUY`解锁标记1，依赖它的`GOLEM_GUY`解锁标记0；其他分支也有类似链 | 08已沿全部前置核验：5个直接锁、46个受祖先锁阻挡，不能只筛自身标记 |
| 相同ID出现重复 | 三叉戟物品掉率与品质数组各有两条STAT_ID=1的重复记录 | 脚本已核实使用数组下标作为运行时ID；原STAT_ID不修改，实际按钮按场景绑定计数，不能据重复内嵌ID判定错误 |
| ALL_COST可能不是累加总价 | 勺子COUNT的ALL_COST约等于FINAL_COST×LEVELS，而非几何级数逐级求和 | 不拿该字段直接计算全树投入；从实际价格算法重算才可信 |
| 前置等级0已核实 | data_controller将0替换为前置get_level_last() | 表示前置满级；实际树内14条此类连接，逐条见08 |
| 正式版范围未知 | 提供文件为Demo，包中有不可用内容配置 | 仅描述这份Demo所含数据，不将其当成当前正式版完整设计 |

## 怎样转成摸猫的树（早期建议）

本节为研究时的早期建议；用户后续要求将重复分支合并、腾出位置给固定设施，最新安排以00第4节及[06适配分析](06_dc升级树适配与风险分析.md)为准。dc原始配置证据仍保留。

| 参考结构 | 摸猫适配方向 | 保留的用户设定 |
| --- | --- | --- |
| 工具主体与分段属性 | 每种猫下分“基础照料”“进阶强化”两段，仍使用现有分支名称 | 短毛→长毛→静电→招财主干不改，不照搬原工具解锁顺序 |
| 基础产量带出其他分支 | 先买该猫产毛量一级，再开放双倍或移动速度；掉率与品质形成另一支 | 不要求前项满级；不同猫只出现用户为它指定的分支 |
| 数量节点带出进阶性能 | 精灵持有上限升级后，开放第二段产毛倍率或效率 | 四类设施仍各自独立上限，上限升级不赠实例 |
| 系统间的阶段连接 | 用实际首次自动产出等里程碑开放后续小游戏和布局能力 | 沿用已有首次自动化引导，不把基础库存强制重新锁住 |
| 不同分支采用不同价格增长 | 小额产量/移速允许频繁购买，扩容与范围能力承担阶段投资 | 所有摸猫费用重新按满足周期、聚猫密度和实际收益校准，原数字仅作证据 |
| 被动与光标独立记录 | 手动操作、全局售价、形态主干在界面中清楚区分 | 原文件的CURSOR范围三段不等于三种手部形态；后两种手形仍等待用户补充 |

**研究结论：**这份文件足以支持“按真实配置重建升级规划”的工作。已交付全量配置表和结构分析；下一层的精确复刻需要继续核对编译脚本和实际技能树界面，才能确认节点坐标、连线、可见性、解锁运算与完整价格公式。当前摸猫00—04的已确认规则保持为基线，以上适配意见尚未写成已采用规则。
