# 毛球满屋｜dc升级树适配与风险分析

> 历史参考，未作为当前饲养方案启用。更早的摸猫规则见[归档旧00](../策划归档/2026-09-17_史莱姆养殖与生产线/00_简明策划案.md)；当前饲养方向见[00](00_简明策划案.md)与[15](15_多猫饲养_荒诞需求与增量拓展.md)。


2026-09-15｜本次按用户方向归并重复分支，并为固定设施安排位置。主节点推进与旁支不作为必要前置由用户最新说明确认；具体排序与收益修正为EA建议，尚未实装或试玩；安排规则统一维护在[00第4节](../策划归档/2026-09-17_史莱姆养殖与生产线/00_简明策划案.md)，参数仍在00第6节。本文负责解释映射、缺口和风险，不另立一套参数。

**建议采用“同一属性只留一个节点，后段等级收进节点；腾出的侧枝放固定设施”。**保留dc的主节点向上推进和周围属性簇形式，但不照搬它的节点数量、完整解锁顺序或原数值。下文统一简称dc。

## 一、根据截图修正：一张向上延伸的长树

用户提供的[图1：下段](参考研究/dc截图/图1_下段.png)与[图2：上段](参考研究/dc截图/图2_上段.png)属于连续区域：从图1底部起步，往上到顶部，再衔接图2底部继续向上。截图可见沿连线分布的对象与属性簇；主节点购买会开放下一主节点、旁支不强制购买，是用户明确补充的操作规则。

**我上一版误把“产量一级”和“持有上限一级”当成了跨主节点前置，现已取消。**内容分类不再被画成四条分别推进的平行线；也不再用旁支等级、实际生产次数或隐藏的AND条件挡住主节点。

### 多路线修正（替代旧M00→M07示意）

旧图将所有主体强制串成一条主链，与用户要求不符，现撤销。[08逐节点复刻](08_dc升级树逐节点复刻.md)已还原本地dc场景的131个按钮及130条连接，提供原坐标图与完整前置表。此后以原版D编号作为猫版替换位置的锚点，保留共同起点、多次分叉、左右长路线和中央被动路线。

本文后续的属性归并、设施替换与风险分析仍是改编建议；不能把它们当作dc原版的完整连接图。猫版具体多路线逐节点对应尚未定稿，旧M编号不再作为研发前置。

| 关系 | 现在怎样处理 | 玩家看到的结果 |
| --- | --- | --- |
| 主节点→下一主节点 | 当前主节点已购买，即开放下一节点购买资格；仍需支付下一节点价格 | 可以继续向上投资，不必先清空周围升级 |
| 主节点→自己的属性 | 已定义的属性同时开放，各项独立购买 | 玩家选择更需要的产量、速度、掉落或数量上限 |
| 属性→下一主节点 | 不建立这种前置 | 完全不买旁支，也不会被属性等级锁住 |
| 同属性重复出现 | 合并进原节点，沿连续等级升级，不附加后段门槛 | 不再找“产量Ⅱ”；树中释放的位置容纳新设施 |
| 主体研发→实体购买 | 分别计费，研发不赠实例；未买实例仍可继续主链 | 推进和扩建是两种投资，不能把部署偷偷变成前置 |
| 纵向浏览 | 起点在底部，向上持续延展；支持回到当前进度 | 两张截图的上下衔接逻辑体现在同一张长画布中 |

猫版规则统一维护于00第4节，dc原版精确编号及连接见08。旧的短毛产量、精灵上限以及先体验后解锁其他主体的门槛均已撤销；小游戏仍保留首次自动产出后的推荐，这是引导规则，不锁主树。

## 二、哪些可以对应，哪些不能硬换

| dc对象／属性 | 摸猫对应 | 适配程度 | 不能直接照搬的部分 |
| --- | --- | --- | --- |
| SPOON | 短毛猫 | 高：都是基础反复操作对象 | 猫要积累满足度并换位，不能沿用工具单次激活频率 |
| SHOVEL | 长毛猫 | 中：更高单次产量 | 长毛还要摸更久，回本要比较每秒收益，不只比掉落数字 |
| TRIDENT及放电属性 | 静电猫 | 中：都可借用范围反馈的分支位置 | 我们确认的是自身满足后触发周围猫产出；不直接继承dc的放电概率或暴击放电分支 |
| PICKAXE／后期工具的位置 | 招财猫 | 低：只能参考后期主体在树中的位置 | 招财以代币为特性，dc工具的货币增长不能代替未完成的代币用途设计；猫种顺序以用户设定为准 |
| MUSHROOM_GUY | 毛球精灵 | 高：自主照料、等待、数量与收益强化 | dc的ANIMATION_SCALE未核实；不能直接当成精灵行走速度和抚摸速度两项的数值 |
| FROG_GUY | 静电毛球精灵 | 中高：范围触发、等待、范围成长 | 我们按每只猫的正常产量发奖励，会随高产猫比例和密度变化；不能按固定伤害或固定产量复制 |
| PASSIVE / CURSOR | 手动升级、全局售价与手部形态位置 | 中低 | PASSIVE不应全部译成“手动”；CURSOR三段范围不是三种手形。全局售价应标明作用于所有收藏 |
| COUNT / COUNT_ADD | 购买实例／独立持有上限 | 只对应职责 | dc字段的实际容量算法待核实；我们的“只有独立上限升级才能扩容”必须保留 |
| 物品掉率／品质属性 | 同名的两类分支 | 高：职责划分相近 | dc合并公式未核实，不能把配置0.01一律当成最终掉率增加一个百分点 |
| 后段重复性能节点 | 逗猫棒、电暖炉的侧枝位置 | 适合改造布局，不是效果等价 | 布局设施改变路径与覆盖，不能继承被替换的“速度Ⅱ”收益、价格和全部前置 |

dc的原始证据见[05研究](05_DirtClicker升级树研究.md)与[配置总表](参考研究/DirtClicker/配置记录总表.md)。本次脚本核实运行时使用数组下标，内嵌STAT_ID重复不能据此判断为运行时错误；没有实例化为树按钮的记录不能当作可任意替换的树节点。

## 三、重复分支怎样归并、固定设施放哪里

下表使用dc的记录键作为来源锚点；原版具体位置已由08核实；本表仍是早期逻辑改编建议，逐项映射需补充08的D编号。**替换的是整组后段属性节点，不是删除前段节点里的原有成长。**

| dc后段来源 | 原升级归到哪里 | 腾出位置拟安排 | 必须重新连接的前置 |
| --- | --- | --- | --- |
| SPOON.DIRT_GAIN[1] | 短毛猫原产毛量节点内的后段 | 固定逗猫棒研发 | 具体跨路线前置待定，不接任何产量、上限或生产事件 |
| SPOON.ANIMATION_SCALE[1] | 短毛猫单一移速节点，按猫换位重新解释和定价 | 逗猫棒范围 | 接逗猫棒研发 |
| SPOON.DIRT_GAIN_CRIT_CHANCE[1] | 短毛猫原双倍概率节点 | 逗猫棒产毛数 | 接逗猫棒研发；不把它改成双倍或代币设施 |
| MUSHROOM_GUY.IDLE_TIME[1] | 普通精灵原CD节点 | 逗猫棒持有上限 | 接逗猫棒研发；该上限不连接下一主节点 |
| SHOVEL.DIRT_GAIN[1] | 长毛猫原产毛量节点 | 电暖炉研发 | 具体跨路线前置待定，不要求任何性能等级 |
| SHOVEL.ANIMATION_SCALE[1] | 长毛猫原移速节点，重新按换位设计 | 电暖炉范围 | 接暖炉研发 |
| SHOVEL.DIRT_GAIN_CRIT_CHANCE[1] | 长毛猫原双倍概率节点 | 电暖炉范围内增产 | 接暖炉研发，不改成全房增产 |
| MUSHROOM_GUY.ANIMATION_SCALE[1] | 普通精灵原抚摸速度节点；行走速度仍是独立属性 | 电暖炉持有上限 | 接暖炉研发，不要求先部署或聚猫 |

这样正好容纳两种固定设施的两个主体研发节点和六个已有性能／上限分支，不凭空增加它们的功能。普通精灵独有的移速等属性另行排布，不为机械对齐dc的节点数而删除。

其他重复记录按相同原则处理：

| 其余重复内容 | 安排 |
| --- | --- |
| 同一精灵的第二段CD、速度 | 收进原节点，等级在原节点内连续购买，不再由持有上限设门槛，不再占另一整组分支 |
| 同一主体多次COUNT_ADD | 保留一个独立持有上限节点；不同设施绝不共用一个上限。dc数值不直接相加 |
| PASSIVE重复产量、品质、售价 | 对应属性合并到其原节点；注明哪些是手动、哪些是全局。不把徽章奖励记录混入付费等级 |
| CURSOR重复范围 | 暂不映射成未定义手部形态或新增手动范围分支；位置可以留白 |
| 暂无对应功能的空位置 | 留给未来内容或收紧布局；不要为填满树而造一个没有实际用途的升级 |

**合并的是展示与成长归属，不能机械合并数值。**例如dc勺子两段产量，在候选指数价格、不逐级取整的假设下，合计约15,962.8；若直接改成九级并一直沿用首段曲线，总价只有约5,643.3，投资规模大幅下降。这只是数学示意，不是已验证的dc实付总价。我们的做法是保留00现有总等级，节点内部连续升级，不设额外阶段锁；后续需要扩级时再算整条投资预算。

## 四、现有增量设计的缺口

| 缺口 | 为什么换成dc树也解决不了 | 建议补法与安排 |
| --- | --- | --- |
| 猫群规模的承载与定价 | 用户已明确无房间总猫数上限，各猫种独立扩容；原“三只到六只”结论撤销 | 已新增各猫种上限分支。仍需验证较大猫群的布局、性能与范围收益，不另设隐藏总数门槛 |
| 同种上限与阵容调整 | 某种满员只影响该种增购，不再阻止其他种类入场 | 本种上限可独立升级；可选的暂存／调整阵容仍可后续设计，但不再是新猫入场的必需修复 |
| 代币扭蛋经济尚未配平 | 用途已确认：代币→独立扭蛋→全局buff收藏；原“没有用途”的结论撤销 | 仍需确定代币获取速度、单抽费用、奖池与重复处理，并验证全局buff叠加 |
| 手部形态与主动操作后期成长未完成 | 后两种形态缺失，人工仍是一只一只摸；收益增加不等于操作方式有新变化 | 不将dc的三段光标范围硬改成手形。手形规则补完后检查是否需要群体操作，但本轮不新增未确认技能 |
| 固定设施没有可靠的摆放收益指标 | 当前只看范围大小，玩家不知道暖炉聚猫后逗猫棒是否还会被经过 | 增加可观察的覆盖猫数、近期有效经过次数、实际额外毛球；先证明升级确实改变收益 |
| 后期自动化绕开小游戏券来源 | 静电范围产出不计满足事件，普通照料弱化后钱包增长与游玩券增长会脱节 | 单独调券的获取节奏，考虑稳定的自动经营里程碑；不直接让每次静电目标掉券，避免瞬间刷满 |
| 全局装饰与设施职责有重叠 | 猫抓柱与普通精灵速度、猫窝与暖炉、铃架与各路掉率同时加成 | 保留“全局温和加成”和“局部布局收益”的区别；先后开放，并在收益预览中说明来源，不能再复制一份buff |
| 缺少后期资金消耗和阶段结束定义 | 现有等级都封顶，临时道具主要来自小游戏，持续收入最终会没有用途 | 先确定本版结束目标与下一阶段内容，不为无限增长临时加入无用途倍率；收藏可以补目标，不能代替全部消耗设计 |


## 五、数值风险：已有证据，而非笼统担忧

版本说明：本节保留v0.5无扭蛋buff时的静态算例；“六只”仅为样本数量，已不是房间上限。全房满员风险已撤销，群体静电风险在独立猫种扩容后更需复测。

以下均为00旧基线参数的静态算例，不是完整仿真。手动单猫换位按0.8秒，无其他升级、buff、收藏、代币或额外寻路；个别行另列条件。[计算记录](参考研究/dc适配审计/静态算例.json)保留假设和结果。P0表示应先处理，否则会破坏主要循环；P1表示在定价与扩级前必须校准。

| 优先级／风险 | 当前证据 | 后果 | 建议修正方向（尚未替换公式） |
| --- | --- | --- | --- |
| 已撤销：全房满员阻止新猫 | 原算例依赖已取消的房间总数上限 | 现在其他猫种数量不阻止新猫入场 | 改为只检查本种上限，不再以此要求强制换猫 |
| P0：静电猫的群体收益近似平方增长 | N只静电猫各由一普通精灵照料，互在范围，每只每七秒满足：总毛球约2N²/7；N从三到六时约2.57→10.29/秒 | 禁止递归仍不能阻止数量与每次覆盖同时放大收益；扩猫群会明显放大问题 | 先按满覆盖猫群校准阈值、费用和精灵产能；覆盖上限／衰减会改变用户能力设定，若采用须另列方案，不能暗加 |
| P0：逗猫棒与暖炉可能互相抵消 | 经过要求先离开再进入；如果猫的换位路径始终在棒范围内，后续奖励为零；扩大棒范围也可能减少穿越边界 | 玩家升级范围或买暖炉反而少赚钱，形成负收益升级 | 建议将“经过一次”按完整换位路径与设施覆盖相交判定，每次真实换位最多奖励一次，保留防重摆和停留刷取；需先验证此解释符合目标手感 |
| P1：手动固定加值让猫种效率倒挂 | 未升级时短毛/长毛/招财约0.303/0.566/0.735毛球每秒；仅手动产量五级后约1.818/1.509/1.471 | 后期主动摸最普通短毛反而普通毛球最高，长毛的高产定位被固定加值削弱 | 手动产毛量可改按猫种基础产量比例增加，或重新校准长毛阈值和基础量；不要直接把反转当作已平衡的分工 |
| P1：普通精灵同价分支回报悬殊 | 单猫基础六秒一轮；首次速度升级约提升20%，首次CD升级约2.86%，两者首价同为八毛球；CD低于换位耗时后，在此场景继续升级不再减少周期 | CD容易成为伪选择；多猫换目标时效果可能不同 | 用一猫、多猫和长毛场景分别定价；按实际瓶颈调整CD每级收益与定价，不照搬统一价格基数 |
| P1：范围精灵削弱普通照料价值 | 六短毛全覆盖时，一静电精灵约0.75球/秒；四只约3球/秒。六普通精灵各照料一短毛约1球/秒；上述未计投资差额 | 后期可能只堆高产猫与静电精灵，满足阈值和普通精灵速度变得不重要 | 同时比较总投入回本、收藏/券来源、范围覆盖率；重新校准范围设施的CD、倍率与价格，而非只比瞬时产量 |
| P1：固定逗猫棒的早期回本过慢 | 只有一只猫每六秒真正经过一次，棒产0.2球：约0.033球/秒；研发加首购20，简单回本约600秒 | 作为醒目的新分支却像收益陷阱；多猫和真实路径会改变结果 | 用当前场上真实经过率报价和定价；调整基础产量、价格或让它更容易覆盖有效路径，不能只保证视觉出货 |
| P1：最后一下决定来源，诱导抢最后一摸 | 玩家只在精灵即将摸满时补一小下，仍领取全额手动加成；反之精灵最后补满会失去人工加成 | 最优行为变成监视隐形进度抢归属，与轻松摸猫冲突 | 建议按本轮有效满足度贡献加权来源收益，或锁定本轮主照料来源；双倍和收藏仍各判定一次，不给两次奖励 |
| P1：品质、掉率和售价容易被错算成同一种加成 | q从零到十，已掉收藏的基础均价约1.85→2.91；另有掉率与售价倍率 | 将品质加值直接当掉率，会错估收入；库存囤货还可放大售价升级的一次性收益 | 保持“先是否掉、再分品质、卖时算售价”的流程，预览含保底与可出售比例的长期收益 |
| P1：售价升级初期很弱，库存多时又突然很强 | 基础品质下售价首级每件多0.37毛球，首费16，要卖约44件才回本；已有大量库存则可马上受益 | 同一费用在不同收藏阶段价值差异极大 | 按首次收藏后、库存积累后的两个阶段测价格；不通过强卖首件维持经济 |

长毛和招财效率的比较仅是普通毛球部分，未评估代币价值；短毛获利较高不自动证明猫种必须全部重新设计，但足以说明“越后期越强”目前没有数值依据。

## 六、下一轮先修什么

1. **先验证独立上限与空间承载：**确保不同猫种不共用总数门槛，再测大猫群布局；未定参数和手形不锁主干。
2. **再保证固定设施值得摆：**先处理暖炉与经过判定，再测范围扩大后的有效触发数；不把“范围更大”默认等同于“收益更大”。
3. **然后压实产能模型：**同时比较手动短毛、长毛、普通精灵、静电猫群、静电精灵和固定设施，统一纳入投入、覆盖、换位与满足周期。
4. **最后定合并后的级数和价格：**每个旧属性节点只保留一条连续等级记录，主节点负责开放自己的旁支，旁支连续购买且不阻挡下一主节点，不重置费用；固定设施有自己的价格，不能直接继承被替换分支的数字。

建议试玩记录实际每分钟收入、升级后收入差、有效覆盖／经过次数、下一次升级等待、不同路线购买比例和小游戏期间的真实积累。已有静态证据足以排出修改优先级，尚不足以宣称某套新价格已经平衡。
新增审计项：扭蛋收藏的全局产毛／移速／售价候选会与原倍率相乘，应把未收藏、部分收藏和高完成度收藏分别计算。扭蛋不进入主树前置，不能靠抽到指定buff补足某个节点的必需产能。

最新招财规则修正：旧算例中“招财猫普通产量5”与手动普通毛球效率比较不再代表当前玩法，保留仅供历史审计。招财猫现在满足后抛币，正面1代币、反面无奖励；原产毛／双倍／物品率／品质四项标为待重设计，不收费。需要改按正面率、满足周期、动画耗时和代币扭蛋价值评估，不能套用其他猫的产毛升级回本。
