## 2. 打开与运行

使用 Godot 导入本目录 `project.godot`，等待资产导入后按 **F5**。首先出现开始菜单，不会直接恢复上次进度。F6 运行当前编辑场景，若选中了旧 `scenes/main.tscn`，看到的是旧原型。

已验证运行环境为 Windows、Godot **4.6.2 stable**、Compatibility 渲染器。项目文件当前仍声明 `4.7` feature，3D physics 配置为 Jolt；这是现存配置，并非已对所有 Godot 版本完成兼容性验证。切换引擎版本时应重新导入和验证 FBX、材质与 SubViewport 演出。

当前布局基准为1366×850，土地逻辑区域为1096×822（4:3）；采用 `canvas_items` 缩放。UI大量通过 GDScript 动态创建，场景树编辑器中不会预先列出所有运行时控件。字体优先使用系统的 Microsoft YaHei、Segoe UI；其他平台的字体替换与小窗口布局尚需检查。

从项目目录启动：

```text
godot --editor --path .
godot --path .
```

将 `godot` 替换为本机可执行文件路径。若只检查逻辑，可使用下文的 headless 测试；确认3D预览、图像遮罩和污渍投影时必须另跑实际渲染。

## 4. 当前玩家流程

1. 启动菜单选择“开始游戏”新开一局，或“读取存档”继续。设置可在开局前修改。
2. 在土地上按住左键拖动刮地；停留只处理当前位置。地层越深越硬，升级强度后正常挖掘手感向下一层迁移。
3. 完全暴露的废料立即入账并跳数字；未知土块自动入库，不强制打断挖掘。
4. 右侧常驻列表直接购买工具、机器人、分析仪和鉴宝机。列表在鼠标位于自身范围时滚动，购买保留滚动位置。
5. 库存选择未知土块：连点剥土，完成后切换到按住拖动甩沙；第二阶段结束揭晓、登记图鉴并获得可售藏品。
6. 可保留、锁定、出售，或主动追加抛光。抛光提高该件售价，不是完成鉴定的必经步骤。
7. 新款及套系提供知识点，独立解锁天赋；机器人负责挖掘，鉴宝机接管库存前两道工序。
8. 顶层达到收尾阈值后补齐、结算并退出，底部补入新层，持续下潜。Esc暂停，普通库存和清理期间后台自动化继续。

### 一帧如何推进

`ea/main._process` 先检查 `session_active`；未进入游戏直接返回。进入游戏后依次调用：

```text
board.step(dt)                  手动输入与显示更新
model.tick(dt)                  机器人、鉴宝机、定期暴露检查及补层
board.consume_find_events()     将已结算事件转成跳字/显示反馈
main._refresh()                 周期刷新余额、库存状态、升级与深度计
model.save_to()                 到自动保存间隔后保存
```

当前模拟dt有单帧上限，不会把挂起很久的一帧折算成完整离线收益。模型通过 `changed` 和 `layers_shifted(count)` 通知变化；后者使土地显示重建、深度条补位。工作台独立接收GUI输入并调用模型，完成后发出 `completed(id)`，UI再调用演出；奖励不依赖动画回调。

## 6. 挖掘、地层与掉落

### 遮罩与强度

- 土地显示用真实图片叠层，逻辑遮罩为512×384。每层保存 `wear`、`mask`、`cleared`；初始未损耗，磨损累计至清除。
- 笔刷以小方形像素簇组成不规则覆盖区域。每个位置只处理当前最上方未清除层；一次采样的剩余伤害不穿透下一层。
- `cleared` 只统计已经清除的逻辑面积，部分磨损不算已清空。渲染淡化、尘土和光标不能替代这个条件。
- v0.3按工具等级与绝对层号的差计算效率。低一级约为适配效率的千分之一，超前工具清旧层更快；不先生成巨大强度和硬度再相除。
- 极端等级差采用很小的可表示正值尾部保护，避免效率直接下溢为零。这不构成正常推进路线，也不是无限精度磨损系统。
- 当前尘土为带重力的方形粒子，颜色从实际地皮纹理采样，避免随机换图后仍用固定层色。

### 连续五活动层

`layers` 始终保存最浅未完成层起的连续五层。层的 `depth` 是绝对编号，数组下标只是当前窗口位置。局部挖空可往下刮；挖穿最深活动层后要清上方残留，不能无限向下钻细孔增加缓存。

地皮从 `assets/soil/RealSoil/` 当前可用图片中选择；现有五张，相邻层排除重复，同图可在后续重现。掉落结果和图片生成后固定，读档不重抽。当前模型使用固定初始种子，新开局可复现同一生成序列。

达到98%时自动清本层残余，结算最后掉落，再允许顶层退场；97.99%不能提前完成。收尾只作用于该层。连续多个顶层完成可连续补层；已有活动层的刮痕保留，完成层的逐像素数据释放。深度计显示和上滚动画不阻塞逻辑结算。

### 掉落和精确结算

每层生成两类带唯一ID的物件：

| 物件 | 生成数据 | 完全暴露后 |
| --- | --- | --- |
| 废料 | `id/kind/position/size/value/collected` | 直接累计钱包，发跳字事件；高级废料金色显示 |
| 古物封存体 | 上述公共字段及内部 `series/variant` | 创建独立库存记录，显示未知土块通知 |

暴露检查覆盖物件整个占地，并检查上方地层。只有 `collected=false` 的物件可结算；结算标志随地层保存。掉落密度、普通/高级比例和深度收益公式见06，不沿用早期“越深废料点数越多”的表。

钱包使用 `Decimal(digits, places)`，精确保存小数余量。跳字按本次显示整数余额的增量生成，因此深层并非永远显示+1/+10；小数累计可使某次普通奖励多显示一个整数。余额的大数显示只是格式，实际购买按精确值比较。

`earned` 当前累计挖掘废料收入，出售直接加 `wallet`；不要把 `earned` 当作已覆盖全部来源的总营业额。

## 7. 清理、鉴定、交易与收藏

### 库存状态模型

`records` 是古物记录数组，`record(id)` 通过ID查找。不要保存数组下标作为永久身份。

| 字段 | 当前含义 |
| --- | --- |
| `id, series, variant, depth` | 唯一物件ID、内部系列/款式、来源层 |
| `estimate` | 已固定的完整市价锚点M，Decimal序列化；不是当前可出售金额 |
| `status` | `raw`、`cleaning`、`identified`、`sold` |
| `step` | 必经工序索引：0剥土、1甩沙；鉴定后为2 |
| `progress` | 三个归一化工序槽；抛光仍单独主动进行 |
| `owner` | 空字符串、`manual` 或 `machine0`…`machine5` |
| `quality, polish` | 是否抛光完成及抛光累计工作量 |
| `locked, new` | 锁定保护、鉴定时是否首次发现 |
| `marks, clods, clod_total, polish_cells` | 按需创建的污渍、土块和投影数据，随库存保存 |

正常流转：

```text
raw → cleaning（可暂停、接管）→ identified → sold
                                    └→ 可选抛光：仍为identified，quality变为true
```

### 未知信息约束

未拥有分析仪时，名称、工作台、通知、筛选与任务提示都不能从内部 `series/variant` 暴露款式。“未知土块（已剥壳）”仍未知。购买分析仪后，现有和以后入库物可显示潜在系列，但不能显示准确价格或提前发知识点。

机器后台可以使用内部系列匹配任务；这不等于UI可以公开逐件所属系列。当前任务显示匿名工序进度。系列机解锁条件必须一起维护，不能入库一个未分析物就亮起对应机器而间接泄露系列。

### 三种输入不可混为一种

| 工序 | 实际实现 | 中断与完成 |
| --- | --- | --- |
| 连点剥土 | 按物件ID生成可复现土块；点击命中才扣剩余工作量，空处无效；可见裂纹和碎屑 | 达阈值只完成第一段；普通玩家点“开始甩沙”，T21自动切工具 |
| 甩沙 | 从物件范围内按住后，以有效鼠标位移消耗随时间补充的预算；带动物件偏移与泥沙粒子 | 静止不加进度，单次大跳变不能瞬间做完；结束鉴定，不自动抛光 |
| 可选抛光 | 对鼠标实际扫过的污渍格减量；有渲染时依据模型投影alpha确定污渍分布，headless回退近似区域 | 干净处不重复加进度；达到阈值后提高品质与售价 |

甩沙当前按累计有效位移处理，没有强制验证每次是否换向，也没有节奏判定器。抛光是2D投影交互，不是对可自由旋转模型做3D表面射线擦洗。

`claim_manual` 会释放该物件的机器任务；`release_manual` 不清掉进度。机器接手后按剩余工作量处理；回到手动工作台时，土块剩余量与已有机器进度对齐。读取存档释放手动owner，机器任务保留。

### 估值、出售与收藏

所有阶段都以同一市价锚点重算总倍率，不对上一阶段价格复利。未知阶段只显示加价比例；第二阶段后开放准确售价与可选抛光收益。完整倍率、逐款基价和取整规则见06。

`identify` 先读取发现状态再登记，保证首件和重复件判断正确。首次款式与首次套系各自只发一次知识点，出售不清图鉴。自动出售默认关闭，只处理当前已定义的未锁定重复普通款；首次发现保留。不要据此推断特别版或剧情物的完整交易规则已经实现。

当前每系列使用目录前五个普通款。保底在 **生成封存体时预留款式**，`draws/duplicate_streak` 记录已生成结果；`discovered` 只记录鉴定结果。二者不能混用。内容在生成后不重抽，预留状态跨层、跨存档保留。

## 8. 升级、自动化与天赋

### 商店与推进预留

当前升级键为 `power/radius/auto/auto_power/auto_radius/auto_move/opening`，另有一次购买的分析仪和六类鉴宝机。铲子及机器人强度是持续成长项，其他属性有限上限。详情和当前价格以06与 `config.gd` 为准。

`purchase_reason/machine_reason/analyzer_reason` 给出具体阻止原因，UI按原因禁用按钮。非铲子强度消费需保留从当前铲子等级升到下一推进层所需的资金；`reserve` 计算预留，`spending_reason` 执行限制。预留仍在钱包中，不是另一种币。修改消费入口时必须同时走这项检查，开发工具例外。

价格缓存仅缓存各项目最近查询等级；预留缓存以等级与当前层为键。不要通过对已取整价格反复乘倍率实现升级，会产生取整漂移。

### 挖掘机器人

所有机器人共享机器人等级，和铲子等级独立。机器人沿直线前进，触边选向内反方向；在采样作业区域停留，待初始表层覆盖清干净再移动。遇到低于自身适配能力的硬层时，会抽样寻找仍可处理的残留；挖穿活动层底部时也会重新寻址。

移动速度只控制位移，不再次乘算局部挖掘强度。当前是轻量抽样寻址，不是全地图路径规划，也不保证完全无重复覆盖。机器人补层后保留平面位置、重新确定工作层。

### 鉴宝机器与队列

- 五台系列机分别处理对应系列；首次鉴定，或分析仪识别出该系列后开放购买。
- 通用机在五个系列都鉴定过后开放，兼容全部当前系列，作为额外工位并行。
- 每台只占有一个物件，通过 `owner` 与 `machine.task` 避免重复领取。
- 只完成剥土、甩沙两个阶段。速度升级作用于两段剩余工时，达到收尾阈值即补齐；不能再次对已减免工时重复应用阈值。
- 暂停某台机器保留任务；手动接管会释放任务，不生成新物件。
- T31可调整未开始/有进度任务优先级；有分析仪后可再选潜在系列优先。T32保存工位开关、自动出售、队列与系列优先级，不复制库存或任务。

### 天赋

| 节点 | 当前效果 |
| --- | --- |
| T00 遗物档案 | 收藏进度显示 |
| T11 异物轮廓 | 强化古物标记轮廓，不识别系列 |
| T12 缺件追踪 | 显示普通收藏补齐保底信息，不改概率 |
| T21 工序衔接 | 剥土结束自动切甩沙工具，不代替实际操作 |
| T22 精品筛选 | 筛选可精修的鉴定物并显示加价 |

天赋花知识点，商店花废料。可免费重置并退回节点成本，不重置发现奖励。自动收尾是基础规则，不需要T21。

## 9. 开盒演出与资产接入

土地为2D遮罩，藏品预览与开盒为独立SubViewport中的3D。当前不是可漫游的3D考古场景。

资产位置：

- `assets/soil/RealSoil/`：正在使用的地皮图片；`assets/soil/` 还保留早期纯色占位。
- `assets/3D assets/`：五套古物及相关贴图。导入的隐藏款不代表现行掉落表已启用。
- `assets/VFX/`：普通、小隐藏、大隐藏的开出特效及待机背景精灵表。
- `scripts/artifact_catalog.gd`：把模型路径、显示名和系列接到预览/演出；现行EA经济不直接使用旧目录售价。

手动鉴定后，`main._show_reveal` 调用 `Reveal.configure` 和 `play_reveal`。演出包括程序生成的盒体开盖、藏品黑色剪影弹出、冲屏回落、恢复导入材质，以及拖动旋转。开盒盒体目前为程序几何体，不是所有系列都使用专属包装模型。机器鉴定在后台完成，不强制弹出演出抢焦点。

新增/替换资产时应同时检查路径、导入结果、包围盒、朝向、材质、预览与开盒缩放。修改显示图不应重抽存档已有层。不要为了纠正一个模型的尺度直接改所有系列共享常量而不回归其他模型。

## 10. 启动、暂停、设置与存档

### 入口状态与输入隔离

| 状态 | 是否推进游戏 | 退出/返回行为 |
| --- | --- | --- |
| 开始菜单，`session_active=false` | 不运行主模拟或自动保存；不自动读进度 | 关闭应用不覆盖已有进度 |
| 开始游戏 | 使用新初始化模型，从零开局 | 进入后启用原自动保存规则；后续保存会替换当前存档 |
| 读取存档 | 成功后重建土地及深度显示再进入 | 无文件禁用读取，读取失败留在菜单 |
| 普通库存/清理/图鉴 | 在线机器人和鉴宝机继续，手动刮地释放 | 退出工作台保存进度并释放手动owner |
| Esc暂停菜单 | 业务模拟暂停，抓取/刮除输入释放 | 再次Esc或返回游戏恢复，不沿用旧按住状态 |
| 设置窗口 | 开局前仍不运行，局内保持暂停 | 应用或取消返回来源菜单；设置内Esc只退一层 |

设置窗口独立阻挡背景输入；升级栏的滚轮不应被背景、深度条或其他窗口触发。当前“暂停”主要由 `model.paused` 控制业务模拟，不是暂停整个 SceneTree 的全部动画；详见限制。

### 文件和格式

| 文件 | 内容 |
| --- | --- |
| `user://ea_save.dat` | 当前v3进度，Godot Variant二进制，非JSON |
| `user://ea_save.dat.tmp` | 写入、flush、关闭后再替换正式文件的中间文件 |
| `user://ea_save.dat.v2.bak` | 第一次读取v2时保留的旧档副本 |
| `user://ea_settings.cfg` | 独立偏好，ConfigFile；减少动态效果与跳过重复演出 |

`user://` 是 Godot 用户数据目录，不是项目目录。可在编辑器打开用户数据文件夹；当前项目名为“考古刮地皮”。不要将实际玩家存档硬编码到仓库路径。

进入游戏后按间隔自动保存，应用退出前也保存。设置中的手动保存/读取只在局内启用；开始菜单设置仅保存偏好。当前仍是单存档槽，无云同步或多槽选择。

保存内容包括钱包和余数、活动层图片/种子/遮罩/掉落标志、内部古物款式及市价、各工序、图鉴保底、升级、分析仪、机器和机器人、锁定、天赋、自动出售及预设。临时粒子、弹窗节点、鼠标按住动作不保存。读取重建显示，不重播历史奖励，无离线结算。

偏好也保留在进度结构中；从启动菜单读取进度后会再加载独立偏好文件，局内 `_load_paused` 目前则采用进度中的偏好。维护时注意这两个入口的现存差异。

### v2 → v3迁移

`load_from` 接受版本2或3，旧档经 `_migrate_v2` 转换：

1. 保留旧钱包、生成结果、图鉴、已有刮痕和旧件市价锚点，不按新逐款表追溯改价。
2. 未完成古物以旧三段完成比例折算新两段进度；已鉴定或售出状态保留，精品状态保留；旧污渍记录重建。
3. 退回已购买的T11/T21/T31及其依赖节点成本，保留T00，清空相关优先级与托管预设。
4. 铲子及已拥有机器人的过低强度一次性补到当前最浅层的适配等级，不发钱，避免旧余额不足时陷入强门槛。
5. 再保存为v3后不会重复退点或重复迁移。反复读取同一未转换的v2源文件仍会重新进行一次内存转换。

这些是迁移实现取舍，不是所有未来版本默认沿用的补偿政策。读档目前只有基本结构检查，没有覆盖任意损坏文件的全面修复。新增字段需补默认值、版本迁移和测试。

## 12. 已知限制与待验证项

以下是交接边界，不是本次文档整理已修复的功能。

- 当前是可运行Demo，不是正式EA发布版。自然首升级、首鉴定时间、长时平衡和低配机器性能仍需真人试玩；深度公式测试不等于真实连续运行千层。
- 当前只有五张地皮复用；五系列普通款使用已有资产。约十张地皮、更多系列、特别版完整掉落/交易、剧情、地雷、转生、离线收益未完成。
- 剥土和甩沙外观仍为占位几何/色块；抛光为模型投影污渍，没有完整包装物理或3D表面清洁。
- 开局生成使用固定种子；不是每次开始都重新随机一张地图。以后若改随机种子，应保留读档不重抽。
- 五层逐像素数据有界，但库存中的售出记录仍留在 `records`，历史物件数量会增加；不能宣称整个游戏所有内存永久恒定。
- 暂停停止业务进度，部分展示Tween/粒子并未全局冻结；减少动态效果主要影响对应尘土和补层表现，不是关闭所有演出。
- 设置当前只提供已有显示辅助、存读档和托管入口，音量、按键重映射、多分辨率完整适配待扩展。
- `ea/main.gd` 仍保留较早的 `_settings/_load/_new_game_confirmation` 等方法。当前设置走 `_render_settings/_load_paused`，新游戏走启动菜单；维护前先看调用链，不要直接恢复旧入口。
- `config.gd` 的 `MANUAL_SECONDS` 是旧候选清理残留；当前手动由工作台输入量控制，机器按 `PHASE_SECONDS` 推进。改旧数组不会改变当前手感。
- 正常路径有独占任务和重复结算保护，但任意外部脚本直接篡改Dictionary不受完整schema约束；自动化维护应调用模型接口。
- 开始菜单不自动读进度、也不在退出时保存空局，这是已修正的行为，不能作为“便捷续玩”重新加回。
