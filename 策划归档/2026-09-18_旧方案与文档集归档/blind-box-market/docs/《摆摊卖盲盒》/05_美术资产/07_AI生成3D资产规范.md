# 07｜AI 生成 3D 资产规范

## 目标

新玩法需要大量可收藏、可出售、缩略图中可辨认的 3D 内容物。AI 生成用于扩大款式数量，但所有模型仍需经过统一整理、技术验收和人工美术判断，不能把未经处理的生成结果直接放入游戏。

## 内容规模建议

### 纵切 MVP

- 2 个系列。
- 每系列按数据表制作9—12个等概率常规款，并按系列配置0—1个小隐藏和0—1个大隐藏。
- 总计约 20—24 个可开出模型。

### 首个完整版本目标

- 6—8 个系列。
- 每系列 10—16 个内容物。
- 总计80—120个基础内容物，另有少量限定变体；当前五个首发系列共57款占位。

先用两系列验证经营循环，再扩大资产数量。没有经过销售与收藏验证前，不一次性生产上百件终稿。

## 系列设计包

每个系列在生成前必须先确定：

- 一句话世界观和目标人群。
- 3—5 个造型关键词、禁止元素和统一比例。
- 主色、辅助色、小隐藏金色演出规范和大隐藏彩虹演出规范。
- 头身比、眼睛位置、手脚结构、底座形状。
- 款式清单与品质类型分配；常规款必须靠姿势、服装、道具或情境形成差异，不能只换颜色。
- 包装正面、系列图标和手机卡片用主视觉。

建议同一系列至少有 60% 的共同形状语言，同时每款保持清楚的正面轮廓差异。

## 模型技术标准

| 项目 | 建议标准 |
|---|---|
| 文件格式 | FBX 或 GLB；推荐最终入库 GLB。 |
| 单模型三角面 | 常规款5k—15k，小隐藏／大隐藏不超过30k。 |
| 材质槽 | 常规款1—3个，最多5个。 |
| 贴图 | 1K为默认，小隐藏／大隐藏可使用2K。 |
| 纹理通道 | Base Color、Normal、ORM；能用纯色材质时不强制全套。 |
| 原点 | 模型底部中心。 |
| 单位 | 1 Godot 单位 = 1 米，导入后统一缩放到收藏物标准高度。 |
| 正面 | 模型有脸、有眼睛的一面统一朝本地 `-Y`。 |
| 顶部 | 本地 `+Z` 为顶部。 |
| 展示旋转 | 系列级额外展示角单独记录，不烘焙进原模型。 |
| 动画 | 首版静态模型，不要求骨骼。 |

肥嘟嘟伙伴系列统一以“袋鼠-骑士”的展示朝向为基准：仅在聚焦预览时先保证脸部正对镜头，再沿统一上轴向左偏转 25°；货架陈列继续直接朝向顾客。该偏航作为聚焦预览配置，不改变全项目的正面标准。

## 生成与接入流程

1. 写系列设计包与款式表。
2. 先生成正面、侧面、背面概念图，人工选择轮廓。
3. 生成 3D 初模，检查脸部、手脚、悬浮碎片和拓扑。
4. 在 DCC 中清理网格、重拓扑、统一原点、比例与朝向。
5. 烘焙／整理贴图，检查许可和生成记录。
6. 导入 Godot 测试场景，验证正面揭晓、旋转、灯光和缩略图。
7. 生成手机图标、未解锁剪影与营销渲染图。
8. 填入数据表并完成开盒、库存、上架、顾客拿取全流程验收。

## 视觉验收

每件模型必须通过：

- 128×128 图标中能与同系列其他款区分。
- 正面展示时脸部不朝上、不背对镜头、不被附件遮挡。
- 自动旋转一周没有明显破面、悬浮面或贴图接缝。
- 白、绿、蓝、紫、金、彩虹背景光下主体仍然清楚。
- 放在摊位货架上时不穿桌、不超出插槽，也不会因尺寸过小难以观察。
- 顾客拿取动画使用的抓取点位于合理位置。

## 数据与命名

当前内容物模型的正式目录：

```text
assets/3D assets/<系列目录>/<系列标识>-<显示名称>（<可选款式标识>）.fbx
```

- `-` 前的部分只用于识别系列，不进入游戏显示名。
- 中文或英文括号内的内容只用于标记“小隐藏／大隐藏”等款式，不进入游戏显示名。
- 模型配套贴图保留在同目录，由 FBX 导入配置引用。
- 活跃游戏数据不得引用 `Bind_Box_Fever美术/` 下的旧模型路径。

`metadata.json` 至少记录：

- `series_id`、`item_id`、中文显示名、品质类型（regular／secret_small／secret_big）。
- 模型来源、生成工具、生成日期、提示词版本和人工修改者。
- 授权／商用状态。
- 推荐展示缩放、额外旋转和抓取点。
- 面数、贴图尺寸和 Godot 导入版本。

## 法务与内容安全

- 不直接仿制真实品牌盲盒、在售角色、商标或包装。
- 不使用无法确认商用权利的训练参考输出作为最终资产。
- 保留生成与人工修改记录，方便后续审查和替换。
- 系列命名、角色轮廓和主视觉在批量生产前先做相似性检查。
