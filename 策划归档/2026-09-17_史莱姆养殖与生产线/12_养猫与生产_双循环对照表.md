# 养猫与生产｜双循环对照表

2026-09-16｜用户确认猫咪持续存在、产物重新蓄积，并将养猫与生产拆为两套并行升级系统。具体操作归属、原料缓冲与销售方式为EA安排，未实装；规则统一见[00](00_简明策划案.md#dual-loop)。

**养猫循环：猫咪蓄积 → 采集原料 → 猫咪恢复蓄积 → 再次采集。**

**生产循环：原料进入产线 → 加工成产物 → 售出换金 → 再投入加工。**

| 对比项目 | 养猫系统：让原料更多、更快 | 生产系统：让原料更有效地变成钱 |
| --- | --- | --- |
| 玩家主要做什么 | 搬猫、采集、安排恢复、扩充猫群 | 送料、摆机器、连接分流、选择加工与销售方式 |
| 循环中的对象 | 猫咪长期存在，体内原料采集后重新蓄积 | 原料投入加工后被消耗或转化，产物售出后变成资金 |
| 核心升级 | 猫咪数量、蓄积CD、每轮原料产量 | 生产速度、处理数量、换金效率、自动化程度、产物种类 |
| 操作与设施升级归属（EA） | 批量抓猫、自动采集、猫咪回流、蓄积设施、培育设施 | 原料输送、缓冲仓、加工设备、分流器、产物运输、自动出售 |
| 第一种瓶颈 | 猫少或蓄积慢，原料不够 | 有原料，但送料慢，机器空等 |
| 对应突破 | 增加猫咪，或缩短蓄积CD | 提高输送量，调整入口与连接 |
| 第二种瓶颈 | 猫已长满，却来不及采集 | 原料送得足够快，但加工入口排队 |
| 对应突破 | 增加抓取数量，建立自动采集与回流 | 提速、增加设备、分流并行加工 |
| 后续瓶颈 | 猫群增大，采集与恢复安排繁琐 | 成品积压、出售跟不上，或当前产物收益不理想 |
| 对应突破 | 区域管理、成组操作、扩大自动采集覆盖 | 自动出售、更快出货、更高售价，或解锁其他加工产物 |
| 玩家需要探索什么 | 猫在哪里聚集、何时就绪，怎样采得上、接得回 | 哪里空闲、哪里排队，怎样分流，哪种产物更适合当前原料和设备 |
| 增量反馈 | 更多猫同时鼓起、更大批量原料弹出、下一轮更快就绪 | 更多机器同时工作、成品持续汇出、实际入账加快 |
| 升级独立性 | 本系统的升级不要求生产树某分支升满，也不直接提高加工速度与售价 | 本系统的升级不要求养猫树某分支升满，也不直接修改猫数、CD或原料产量 |
| 给另一系统提供什么 | 产线所需的原料 | 可重新投资养猫的资金；EA建议共用基础资金，不另加两套货币 |

**两棵树不交叉设研发前置，但经济会相互影响：原料不够，产线会空等；加工不够，原料会积压。玩家根据现场情况决定下一笔钱投哪边。**

EA建议在中间设置原料缓冲仓。猫只进入采集设施，采集后返回；原料进入后续加工线。这样保留“拖猫进设施”的操作，同时让加工速度不会直接改变猫咪的蓄积CD。

“换金效率”需要区分：**卖得更贵**提高单位价值，**卖得更快**减少成品积压。解锁新品种产物也不保证更划算，还需比较耗料、加工时间与售价。

Demo可从原料仓连接预置的基础加工／出售设备开始，先维持简单收入；新产物和复杂加工留到后面展开。两套升级各自有入口与分支，不意味着要切换两个场景；全屏内可同时观察猫群与产线。
