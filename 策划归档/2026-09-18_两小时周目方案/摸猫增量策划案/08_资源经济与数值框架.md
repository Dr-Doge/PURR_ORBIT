## 叠层公式候选（设计提案）

定义：n为完成的毛层数，B为一层基础产量，M为已生效产量倍率，a为每增加一层的额外增益系数。

候选总产量：`Y(n) = B × M × [n + a × n × (n - 1) / 2]`，其中`a > 0`。

这个候选让第k层贡献`B × M × [1 + a × (k - 1)]`，每层CD仍相同。对比n次单层收割，收益比为`1 + a × (n - 1) / 2`。公式仅用于试算“层数越多收益明显更高”，尚未确定采用。

| 纯数学示例：a=1、B×M=1 | 等待多层后收割 | 等时长反复收第一层 |
| --- | --- | --- |
| 1层 | 1 | 1 |
| 2层 | 3 | 2 |
| 4层 | 10 | 4 |

以上数值不是猫种初值或售价。未确定毛层上限前不能将公式无限外推：无上限且线性增长每层价值，会使持续等待越来越占优。需要验证存钱升级的即时回报能否与等待竞争，再决定上限或高层曲线；不能未经确认取消叠层优势。

## 速度与产量分开

| 变量 | 影响 | 试算注意 |
| --- | --- | --- |
| 基础毛层CD | 多久增加一层 | 同一条件下后续每层同CD |
| 喂食产量倍率 | 一次结算拿到多少 | 增益在生长或收割时确定，待D01 |
| 祭坛速度 | 全局生产节奏 | 作用系统与叠加顺序待D04 |
| 外星猫速度 | 周围猫的毛层CD | 范围和多猫重叠待D04 |
| 工人处理能力 | 实际每秒完成多少工作 | 不能用名义产量替代工人来不及处理后的真实收入 |

速度换算候选：若生产速度乘数为S，可用`有效CD = 基础CD / S`。不能同时再对同一来源重复减CD；外星猫的CD缩短与全局速度如何合并，定稿前不填具体百分比。

## 价格、回本与运行率

设计提案：重复购买成本可采用`第k次费用 = 初价 × 增长系数^k`，但猫、工人、设施和各强化分支分别校准。新机制首购用独立定价，不能靠统一指数把关键玩法长期锁死。

估算回本时间：`购买成本 / 每秒新增净收益`。净收益要扣猫粮等持续消耗，并考虑猫被娱乐占用、故障停产和工人不足。一次中奖不能当作稳定的平均收入。

娱乐每秒期望收入候选：`有效运行率 × 获胜概率 × 平均奖品售价 / 单轮时间`。维修前后比较的重点是运行率恢复，不是给维修工人再叠一份奖励。

岗位压力可用`任务到达频率 × 单次占用工时 / 岗位人数`估计。持续超过1意味着积压会增长，是增加工人或调整分工的信号；此计算只用于调试，不必展示给玩家。

## 必须验证的风险

| 风险 | 需要观察的情况 |
| --- | --- |
| 工人总在第一层收割 | 自动化反而取消玩家的叠层收益；验证目标层策略 |
| 猫粮持续亏损 | 购买喂食器后净收入倒退；区分故障惩罚与正常经营成本 |
| 加速相乘失控 | 祭坛、外星猫、日光浴叠加让CD趋零 |
| 静电、招财、转化递归 | 一次事件不断生成新的同类事件；判定边界必须先明确 |
| 转化概率卡流程 | 未转成特殊猫时无法赚到下一设施；不要把体验顺序写成随机硬锁 |
| 工人维护收益不明显 | 故障太少导致节点无用，或故障太密让维修永远追不上 |
| 升级提价超过增长 | 玩家进入长时间无选择等待，失去“突破瓶颈”反馈 |

下一轮最少需要一组基础猫CD、单层产量、抚摸耗时、首工人成本与效率、猫粮消耗、娱乐回报和故障频率，才能进行完整数值模拟。当前尚无已验证EA价格表。

## 周目扭蛋的数值框架（设计提案）

设当前新增可抽系列集合为S，每套件数为m，已经获得件数为c，则剩余抽数为各系列的`m - c`之和。不放回保证成功抽取一次就减少一个剩余名额；若单抽统一费用为k，完成剩余收藏所需代币为`k × 剩余件数`。单抽费用是否统一仍未定。

系列buff可从`B = 满套强度 × f(c / m)`试算，其中f单调递增、第一件即提供正加成。是否线性、满套额外奖励、不同系列同类buff如何叠加均未定。继承旧系列时保持既有收集度与加成，不因进入新周目再次乘算同一收藏。

| 风险 | 需要校准的关系 |
| --- | --- |
| 首枚代币迟迟不来 | 核心设施要求早期出现；首掉落保障应单独设计 |
| 猫群经营与代币脱节 | 不能经营越来越强，抽取进度却只按固定时间等待 |
| 只收第一层刷代币最优 | 代币按收割次数判定可能反向惩罚叠层；需比较按时间或产量折算等方案 |
| 永久加速引起复利失控 | 永久buff、祭坛、外星猫、工人效率的叠加必须分别标记来源 |
| 第二周目奖池更大却更慢 | 系列数量、每套件数、抽取费用与代币效率一起调整 |
| 剩余代币囤积 | 若继承过多，下一周目可能立即抽空；若清零又需清晰提前说明，规则待定 |
| 本周目过早或过晚抽完 | 必需抽数要匹配设施体验，避免没见到主要联动就重开或后期只剩空等 |

不重复消除了为重复品付出的抽数，但没有消除代币掉落等待。完整平衡需要同时记录每周目净毛球收入、有效代币速率、剩余抽数与继承强度。


## 按周目校准经济

第一周目不能依靠娱乐、招财或祭坛才能获得足够代币完成奖池；第二周目经济不以祭坛收益为前提。各轮抽取总成本应配合本轮开放的收益来源与玩法长度，而不是按全部设施同时存在来平衡。后续系列buff可以强化未来系统，但首抽需要有本轮就能感知的效果，此为设计建议。

升级费用可以调整局内节奏，却不能替代周目开放门槛。继承buff让钱足够时，未开放设施仍不可购买；逐轮数值验证需要同时记录本轮已开放机制的体验时机，避免玩家过早抽空奖池而跳过新玩法。
