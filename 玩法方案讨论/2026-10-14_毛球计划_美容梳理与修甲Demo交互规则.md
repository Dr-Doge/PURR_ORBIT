## 1. 设计原点：操作少，处理对象有变化

玩家经营船舱里的猫咪美容服务。猫是顾客，玩家按它的要求梳理卫生、修剪指甲，服务质量决定报酬。目标是快速服务一位又一位顾客，重复操作仍有不同处理对象、演出与反馈。

**交互变化不超过三种，首版只做两种：按住拖动梳理、按住划线修甲。** 两种都使用鼠标左键；区别在于前者连续作用于经过的区域，后者按一次完整切线判定修剪位置。灰尘、打结和垃圾属于同一种梳理操作中的处理对象，不各开一个小游戏。

用户实玩《Scale the Depths》后的拆解：捕鱼通过按住引导鱼钩；处理鱼时按住移动刀刃，普通鱼鳞通过耐受度改变重复次数、寄生虫要求慢刮、藤壶要求快速反复刮；处理头、鳍、尾时改为单次或重复点击。**借鉴的是同一动作下的对象规则变化，不复制每只猫一套复杂玩法。**此处是用户体验记录，未补造游戏版本和录屏证据。

## 3. 梳理：同一个工具，处理不同对象

**按下左键 → 工具沿鼠标路线移动 → 判断经过什么对象及速度是否合适 → 对该局部累积处理进度 → 覆盖物消退、露出干净底图。**松开左键停止处理，已处理的地方和未完成对象的进度保留。

| 对象 | 原型建议的处理规则 | 画面反馈 | 判断重点 |
| --- | --- | --- | --- |
| 灰尘／普通乱毛 | 在舒适速度范围内扫过即可逐步清除；不同顾客可有不同耐受量，需要重复经过不同次数。 | 工具经过处尘层变薄、毛变顺，少量碎屑脱落。 | 不是划过一次就整猫变干净，也不是静止按住自动刷满。 |
| 毛结 | 仍按住拖动，但要求较慢梳过；超出该对象速度范围时不获得有效解结进度。是否同时扣评，按统一疼痛规则决定。 | 结团逐渐松开、缩小，最后恢复顺毛；过快时猫缩一下并有醒目提醒。 | 通过放慢同一动作完成，不另加连点、节奏条或新窗口。 |
| 垃圾／粘附物 | 仍按住拖动，以短距离反复经过或规定次数处理；往复速度保持在顾客可接受范围内。 | 粘附物逐步松动，完成后弹开／消失。 | 次数和往复要求可以变化；不要求玩家以超过疼痛阈值的速度强行处理。 |

对象到规则的映射为首版建议，可在试玩中调整。参考游戏的“藤壶快速刮”不等于猫美容一定需要危险高速操作；若采用快速型垃圾，必须有可完成且不会必然扣评的速度区间。

### 判定与图层边界

- 猫的底图、覆盖层和有效区域共用局部坐标；脸、眼睛、背景等非服务区域不因经过而被擦掉。
- 梳理不仅是覆盖层透明度下降，还需保存该对象的剩余处理量及完成状态。速度不满足规则时不能只在视觉上擦掉、逻辑却仍未完成。
- 对鼠标连续路径做扫线判定，避免快速移动漏掉中间区域。处理量应依据有效路径／时间等一致单位，不按每帧固定加值，避免高帧率更容易完成。
- 速度按“猫身体局部距离／实际时间”或同等归一化单位计算，避免窗口尺寸变化、镜头缩放改变难度。**原型建议**连续采样并平滑短时噪声；重新按下时不把旧位置连成超长划线。
- 普通鼠标没有压力输入。“太大力”先以过快或持续粗暴操作作为可检测代理，配合猫的反应表现；不宣称检测了实际手部压力。
- 评价扣减仅在有效服务接触中触发。在背景快速移动、不按键移动、界面操作不造成疼痛。
- 同一次持续过速不能每个渲染帧重复扣评。**原型建议**按一次违规段或短间隔限频记账，明确提示原因；计费方法仍待试玩。
- 最后一小块边角应提供可配置的完成容错；容错可以收尾覆盖层，但不能绕过未处理的独立毛结、垃圾任务。比例未定，不默认沿用历史98%。

## 4. 修甲：按一条切线决定浅、合适或过深

进入修甲步骤后，展示可读的猫爪／指甲区域。每根待修指甲标出合适区间，并区分外侧多余部分和靠近爪子的血线区域。玩家按住左键，从一侧划到另一侧；鼠标尾迹或刀剪轨迹显示本次切线。

| 结果 | 触发条件 | 行为与反馈 |
| --- | --- | --- |
| 没有剪中 | 没有横穿有效指甲区域，或划线未到达另一侧。 | 不算一次修剪，不推进，也不扣评；给轻提示。 |
| 太浅 | 有效切线位于过浅区域，仅剪掉外端一部分。 | 指甲确实变短，保留剩余待剪状态，玩家继续修剪。用户未要求浅剪扣评，首版不额外扣评。 |
| 完美 | 有效切线穿过当前指甲的合适区间。 | 该指甲完成，短促清脆反馈和猫满意反应，进入下一根／下一部位。 |
| 太深 | 有效切线越过安全界限，进入血线区域。 | 猫缩爪／叫一声，评价降低，明确告知剪深了；不额外扩展血液、伤病与医疗系统。 |

**原型判定建议：**用一次按下到松开的轨迹组成修剪手势，检验是否真正跨越指甲左右边界；以切线与指甲轴线的交点位置判定深度，不以鼠标松开位置判定。不沿整条轨迹对同一根指甲多次切剪；同一手势只提交一次结果。

曲线手势、同一划线跨过不同深度时，建议以有效横穿段中的最深位置判定，避免曲线擦过血线却被当作完美。完美带在本根指甲的局部坐标中定义；浅剪后更新可见轮廓，不能要求玩家剪到已经不存在的外端。斜线容错和完美带宽度待试玩。

**避免卡单的建议：**剪得过深时，本次已剪下的指甲记为完成，但留下评价损失，不让玩家对同一处反复剪深来推进。若采用其他恢复规则，必须能继续完成订单；首版不加入等待伤口恢复的系统。以上为开发边界建议，不改用户已确认的“过深扣评”。

## 5. 顾客、评价和快速结算

### 首版状态流程

**到店 → 展示本单需求 → 进入近景 → 梳理／修甲 → 全部要求完成 → 按评价结算一次 → 数字与货币图标出现 → 顾客离场 → 下一位进入。**

每单可以只要求梳理、只要求修甲，或两项都要；用于展示差异。首轮预设顺序建议为：普通灰尘梳理、加入毛结／垃圾的梳理、独立修甲、组合服务。具体顺序、猫种和任务数量可调，不是正式关卡设计。

| 项目 | 规则 |
| --- | --- |
| 需求展示 | 用少量服务图标和短文字说明本单要求；完成项自动勾选，不给所有猫强制塞满所有任务。 |
| 评价 | 原型建议从较高评价起步，只对已判定疼痛／错误处理扣减；满分、下限、扣减和奖励倍率集中配置，尚未定数值。 |
| 疼痛提示 | 立刻表现猫的反应与评价变化，不能服务结束才让玩家发现被扣钱；不阻塞鼠标操作。 |
| 报酬计算 | 建议按“本单基础报酬×评价对应倍率”计算；取整方式、低评价最低报酬和各任务基础价待校准。 |
| 发钱时机 | 完成全部必需操作后一次发放，写入测试钱包；处理过程可有碎屑与动作反馈，不先发同一笔最终报酬。 |
| 快速演出 | 在猫／服务台附近跳出“+金额”和货币图标，资源栏同步增长；完成反馈结束后接下一位，无领取按钮和结算弹窗。 |
| 结算去重 | 订单ID和已结算标记防止重复发钱。切场景、重试、重复回调不得再次给已发报酬。 |

前版“每一步先入账毛球，再给整单奖励”的提案在本次原型中被替代。若后续考虑收集服务产生的猫毛用于毛毡，另行定义物料接口，本轮不能顺便新增独立毛币、兑换和锻造系统。

## 6. 可游玩Demo的范围与验收

首版必须包含：独立Godot 4.7.1场景、近景梳理、三类覆盖物的可调规则、划线修甲、评价扣减、自动结算和连续接待。至少两种外观／处理区域不同的顾客供比较；先用一只猫完成底层，再接第二只。

暂不以前置要求加入：完整升级树、工具成长经济、自动化工人、打捞、盲盒／锻造、十种猫各自小游戏、复杂排队与经营、正式存档迁移。原型的目的先验证主交互，工具升级移至下一步。

| 验收点 | 要展示的实际操作 |
| --- | --- |
| 局部可见 | 在一半身体完成梳理后停手，已清理和未清理区域同时可见；返回后进度不清零。 |
| 同动作不同技巧 | 正常扫灰尘，慢处理毛结，往复处理垃圾；不弹独立小游戏、不增加新输入键。 |
| 速度有代价 | 故意过速梳理，看到猫疼痛和评价降低；正常速度可完成，不需要违规则才能处理某对象。 |
| 修甲三结果 | 实际划线演示浅剪可继续、完美完成、过深扣评。无效划线不能假装切成功。 |
| 报酬体现质量 | 相同需求下比较正常和失误服务，结算金额不同、各发一次，图标和钱包一致。 |
| 节奏连贯 | 不用开发菜单连续完成多个顾客；无弹窗领取、无卡单，正常玩家能从头完成。 |
| 输入稳定 | 不同窗口尺寸和帧率下，梳理速度、指甲切线和区域判定一致；UI、失焦、转场期间输入不穿透。 |
| 原型隔离 | 正式主场景和旧测试原型保留，测试不会读取／改写正式存档。 |

具体速度、耐受度、次数、区域大小、评价、报酬和转场时长均为待调参数。开发选用的初值须明确标为原型试玩值并集中导出；实施后在17号数值总表新增本原型专节，不用旧毛层、165像素收割或一小时节奏来代替本次调参。

## 2026-10-15 v2：双猫差异化操作（已实装）

普通三花猫从头侧开始向尾巴轻梳（画面左→右），有效扫过即清洁；反向与从身体中段起刷不清洁，过快接触污物降评。毛结要更慢地顺梳，垃圾按住向上轻挑。机器猫允许快速双向擦拭，普通油污／指印需要多次摩擦；特殊积灰上下交替3次、粘附油块左右交替4次，不能用同方向重起或微小抖动冒充往返。
