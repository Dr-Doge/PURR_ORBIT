# 《Purr Orbit／毛球计划》美容店主交互与Demo待办清单

日期：2026-10-14。用途：明确下一阶段策划、美术与程序的工作顺序，先验证主交互，再扩展内容。

**本阶段目标：让玩家愿意反复给猫做美容，并能通过工具升级直观感到操作效率变高。** 猫作为顾客提出服务要求，玩家完成相应操作，得到毛球；毛球用于升级，也为后续毛毡／锻造副玩法提供资源。

本清单依据今天两场会议及会后用户指定的美容店方向整理。所有未勾选任务均未在本轮实施；负责人和截止时间会上未明确，接手时填写。本文属于玩法讨论和原型筹划，不代表正式策划已经替换。

## 1. 本轮工作的边界

| 内容 | 本轮口径 |
| --- | --- |
| 当前首要任务 | 定义猫咪主交互，搭建可以亲手操作、连续重复的Demo。外围系统不能替代这项验证。 |
| 美容店形式 | 会上属于候选提案；本清单按用户会后指定的方向筹划：猫是顾客，玩家为其提供服务。 |
| 第一种核心操作 | 以梳毛为首版建议：乱毛变顺毛，工具经过的地方立即发生局部变化。吹风机作为替换候选，先不同时制作完整两套。 |
| 猫种差异 | 先把一只猫做通，再用两只外形差异明显的猫比较交互；通过试玩后才扩到五只。 |
| 交互场景 | 船舱承担接待和猫的活动，近景承担主要服务操作。保留猫四向或八向移动、待机和完成反馈。 |
| 收益与成长 | 每个有效服务步骤给小反馈，整单完成给明显奖励；统一使用毛球，不另设美容金币或局外货币。具体收益分配待设计。 |
| 操作限制 | 不以高频连点或在同一小区域狂搓为核心。速度要求、错误处理、减少报酬都先验证，不直接认定为必需。 |
| 副玩法 | 毛毡／锻造及盲盒仍是后续资源去向和目标，本轮只明确接口，不优先制作完整副玩法。 |

### 建议的最小可玩循环

**猫进船舱 → 显示服务要求 → 点击接待并进入美容近景 → 使用工具处理身体上的待服务区域 → 猫给出完成反馈 → 毛球结算 → 猫离场／下一位到来 → 用毛球升级工具 → 更高效完成下一单。**

首版顾客来访采用预设顺序即可。离场再回来、随机客流、店铺扩建等系统以后再定，不影响先验证上述循环。

G02—G08为本项目待设计内容，不是已经验证成立的玩法。建议首版默认保留未完成区域的进度；不能重新回到“鼠标离开即全部清零”的体验。

### 两只猫的最小差异草案

| 测试猫 | 同一套梳毛规则下的区别 | 应验证什么 |
| --- | --- | --- |
| 普通猫 | 身体集中，较宽的连续区域，几次清晰的扫过即可看见大块乱毛变顺。 | 基础操作是否顺手、局部变化是否足够爽、玩家是否愿意再做一单。 |
| 长腿猫 | 躯干与长腿形成不同方向的区域，玩家自然改变工具路线；避免把腿做成难以点中的细线。 | 只改变轮廓和处理路线，能否产生新鲜感，又不增加手腕负担。 |

这只是样本建议。若现有素材更适合普通猫＋长毛猫，可换样本；仍须保留明显的形态和操作差异。首轮不要求每种猫各做一套独立小游戏。

### 开发接手时的复用判断

当前正式入口为`毛球满屋/scenes/3D scene.tscn`，现有`毛球满屋/scenes/测试场景.tscn`仍引用`prototype_harvest`脚本，是猫身随机长毛、摘毛的旧原型。二者都不是美容店Demo。

- **可评估复用：**船舱背景、已有猫的移动与待机素材、近景切换组织方式、独立测试场景的菜单与输入隔离。
- **必须新增：**顾客订单状态、乱毛／顺毛素材、局部美容状态、工具判定、操作质量提示、服务结算与连续接单。
- **不能直接照搬：**旧原型的“随机长出无限毛头”“点击摘取”和毛王、偷毛贼等规则。已有放大能力不等于已经实现本次局部梳毛。

接手时重新核对最新代码和素材；以上仅依据2026-10-14读取的工程，快照提交`1daf85bc`。本轮没有运行或修改引擎。

## 5. 推荐推进顺序与试玩决策

**G01—G03 → A01—A03与D01—D04 → 单猫试玩 → G04、G07 → A04与D05 → G06与D06 → D07—D08 → 决定是否扩到五只猫。** G05与各步同步；G08先作对照测试，保留规则以试玩结果为准。

| 验证点 | 观察方式 | 需要返工的信号 |
| --- | --- | --- |
| 看得懂 | 首次进入时少讲解，观察玩家能否找到待处理区域、操作工具并完成。 | 反复问“我要干什么”，靠猜测或乱点推进。 |
| 操作有反馈 | 观察每次经过区域，猫身、声音和资源反馈是否同步。 | 只看进度条，猫身变化不明显，像在拖动鼠标刷计数。 |
| 愿意重复 | 让玩家完成数单，询问想继续、想跳过或想停止的原因。 | 主要想尽快逃离近景，升级吸引力也无法缓解疲劳。 |
| 差异成立 | 比较两只猫的路线和特殊区域，不提前告知所谓差异。 | 玩家只感到换图，或第二只猫只是更麻烦。 |
| 成长可见 | 体验升级前后同类订单。 | 只看到数字变大，实际操作没有变化；或升级后美容步骤完全失去意义。 |
| 失误可理解 | 若加入质量限制，观察玩家能否主动调整。 | 不知道哪里做错、错误不可挽回、反复被扣钱却没有提前提示。 |

首轮以**数单可连续完成、能购买一次工具升级、能比较两只猫**为内容范围建议，不承诺旧版一小时节奏。单猫验证不成立时，先改输入与反馈，不用扩猫种、加盲盒或加经营系统来遮盖问题。

## 6. 主交互通过后再安排

- [ ] **P1：扩到五只猫。**沿用同一服务框架，用轮廓、服务区域、特殊毛发和完成反应形成差异；先列差异表，再生产素材。
- [ ] **P1：增加第二种完整服务。**在剪指甲、解毛结、清理脏东西、机械猫擦划痕中选择，确认工具切换与收益节奏，不把每项都做成独立弹窗小游戏。
- [ ] **P1：设计短期工具成长。**先扩作用范围和操作效率，再考虑新增工具能力；具体节点数量、费用与成功条件根据试玩确定。
- [ ] **P1：对接毛毡／锻造。**明确服务提供毛球、副玩法消耗毛球、作品加成反哺服务的接口；不新增一套货币，副线自身设计另列任务。
- [ ] **P2：完善顾客和经营。**猫的回访、客流、等待、店铺扩建与长期关系，主交互成立后再评估。首版不增加饥饿、需求衰减等负担。
- [ ] **P2：主场景辅助互动。**船舱内的轻抚摸、低额产出或批量操作，本次会议明确不是优先事项。
- [ ] **P2：长期收藏和自动化。**先明确自动化保留哪些人工价值，再安排完整升级树、盲盒系列与后期节奏。
