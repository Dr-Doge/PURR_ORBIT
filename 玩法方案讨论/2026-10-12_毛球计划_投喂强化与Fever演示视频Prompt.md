## 3. 核心动作规范：一次点击，一粒零食，一次进食

### 3.1 鼠标点击如何被看见

光标停在猫胸前或身体侧边的可点击区域，避开嘴和眼睛。每次点击时：

1. 光标短促压缩、变暗，表现按下。
2. 接触位置出现一次小型圆形点击脉冲，持续约0.1秒。
3. 光标恢复原状，表现释放。
4. 释放后才飞出这一次对应的零食。

点击脉冲只出现一次，不持续闪烁。鼠标可以停在同一处重复点击，但每轮都必须重新显示按下与释放。光标仅悬停、移动或保持按住，都不能连续生成零食。

不增加真实鼠标设备、真人手臂或玩家角色。点击音可辅助，不能代替可见点击动作。

### 3.2 单次投喂的动作链

| 次序 | 必须出现的画面 | 不允许的替代 |
| --- | --- | --- |
| 点击 | 光标压下、一次脉冲、恢复 | 光标静止但食物自行生成 |
| 投出 | 1粒零食从画面下方固定来源飞出 | 自动喷一串零食、几粒同时存在 |
| 接近 | 零食沿短抛物线接近猫嘴 | 猫还没看到食物就反复咀嚼 |
| 张嘴 | 猫头前探、嘴夸张张开一次 | 一个零食对应多次独立大张嘴 |
| 咬住 | 零食到达张开的嘴后被咬住 | 零食穿过脸、落在台面、粘在胸口 |
| 吃下 | 嘴闭合，零食完全消失，短促咀嚼 | 零食仍漂浮、复制出残余零食 |
| 结果 | 普通阶段成功亮一次并新增1格 | 猫还没吃下就先升等级 |
| 复位 | 恢复可接下一粒的坐姿 | 长时间停顿，下一轮因而超时 |

普通阶段每轮约1秒，Fever每轮约0.8秒。通过缩短抛物线距离和咀嚼次数满足时长，不跳过点击、张嘴或咬住。夸张体态来自快速前探、嘴张大、身体短促压缩和迅速回正，不来自长慢镜头。

### 3.3 普通阶段的一秒动作节拍

以下为剪辑对齐建议，不要求工具自动精确识别毫秒：

| 相对本次点击的时间 | 动作 |
| --- | --- |
| 0.00—0.10秒 | 可见的光标按下、释放和点击脉冲 |
| 0.10—0.28秒 | 单粒零食飞向猫嘴 |
| 0.28—0.43秒 | 猫张嘴一次并咬住 |
| 0.43—0.63秒 | 嘴闭合，食物消失，快速咀嚼 |
| 0.63—0.78秒 | 成功闪亮，新增1格，等级加1 |
| 0.78—1.00秒 | 短暂恢复，概率切到下一轮 |

Fever可将结果与恢复压到0.8秒内，但仍按同一因果顺序。最后红区误点也必须完整对应一次投出与一次吃下；这次不新增成功格，而是结束Fever。

### 3.4 白光变身的必经过程

**先完整遮挡，再换形象，最后显露。**

- Fever结束后，先停止彩色闪烁。
- 白光从猫的身体内部迅速增强，覆盖头、耳、脸、躯干、四肢、尾巴，变成完全不透明的亮白剪影。
- 完全覆盖期间，看不到原三花花纹，也看不到绿色、新眼睛或触角。
- 在这一完全不透明的遮挡期间，切换为外星猫的精灵形象。
- 白光逐渐消退后，才露出完整的绿色外星猫。
- 猫脚底锚点不变，设备与镜头不移动，不能在变身时跳到别的位置。

白光只覆盖整只猫并带少量外沿辉光，不白屏、不遮住全台或整个房间。不能用半透明绿色叠层、逐渐染绿、直接跳切或两种猫交叉淡化代替此过程。

## 8. 原生生成与后期合成两种用法

详细Prompt提供的是目标时序，不能保证视频模型一次就准确做到16次点击、精确中文和全部概率。建议生成后逐帧核对；点击因果链、进食动作和白光遮挡是保留素材的主要标准。

### 原生生成

直接使用共用Prompt与对应大段Prompt，保留全部光标、UI和指针要求。若猫动画合格但数字或指针错误，可以后期遮掉原UI再重做，不能把错误结果作为完成版。

### 后期UI合成

优先让模型生成猫、零食、设备、镜头与白光变身，精确数字、方格、时机条由后期统一叠加。追加以下段落：

```text
采用后期UI合成版本，以下要求替换前文精确UI绘制要求：保留设备后方显示板与边框，板面留空供后期叠加；不生成中文、概率、等级、八格内容或乱码。信息卡位置预留，不生成实际文字。抚摸只表现产出和飞向资源栏的毛球，不生成+3和+13数字。Fever底部时机条区域预留，条与指针由后期制作。
猫的身体、嘴部、投出的单粒零食和白光遮挡变身仍严格按原段落发生。不要因为不生成UI就跳过对应成功、误点和结束演出。白光必须由普通猫开始，覆盖全猫，再退去露出外星猫，不能只预留一个变身空白。
```

### 光标与点击也后期制作时

仅在选择后期输入合成时，再追加：

```text
鼠标光标和点击脉冲由后期统一制作，因此本次不生成任何光标。每个已指定的点击时刻，仍只生成一粒零食并完整演出一次张嘴咬住、吃下和结果。按投喂起始时刻保留约0.1秒的输入表现空档，让后期能在零食飞出前补上光标按下、释放与点击脉冲。最终视频必须清楚表现每一轮由玩家点击触发，不能交付无光标的自动投喂版本。
```

最终每轮要保证：鼠标按下与释放在先，零食出发在后，进入张开的嘴后消失，吃完再更新结果。点击位置跟随猫的可点击身体，但不要遮住嘴。不要同时保留生成光标与后期光标。

设备板上的后期UI跟随板面透视，镜头聚焦后稳定显示；猫下方时机条作为稳定屏幕UI。B段镜头缩放的第一秒、D段回退的前两秒，可以先不显示精确文字，镜头稳定后再出现。

白光覆盖采用猫身体的遮罩或精灵白化，使原猫整身完全不可见；更换形象发生在白光完全不透明时。猫自身闪白不等于把整幅画面提亮。若模型只做突然换猫、没有完整遮挡，不能靠加一次全屏闪光冒充这一演出。
